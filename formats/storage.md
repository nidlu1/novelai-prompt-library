# 샘플과 재사용 패키지 저장 규약

RAW·REG·REFINE, 재사용 패키지와 패키지 자체 이미지의 파일 위치·JSON 형식을 정의한다.

샘플 작업은 [reg.md](../workflows/reg.md)·[refine.md](../workflows/refine.md), 대표·서브 이미지는 [package_images.md](../workflows/package_images.md), 분류·정렬은 [prompt_rules.md](prompt_rules.md)를 따른다.

구조 예시: [RAW](storage_examples.md#raw-예시) · [REG](storage_examples.md#reg-예시) · [REFINE](storage_examples.md#refine-예시) · [패키지](storage_examples.md#패키지-예시) · [패키지 자체 이미지](storage_examples.md#패키지-자체-이미지-예시).

이 JSON은 NovelAI 메타데이터에서 필요한 값을 선별한 라이브러리 저장 형식이다.

## 적용 상태

v6의 도구를 라이브러리 저장 구조와 갤러리 규칙에 맞춰 적용했다. 현재 실행 가능한 도구는 다음과 같다.

### 실행 가능한 도구

- `scripts/extract_metadata.py`: PNG·정지 WebP 메타데이터 추출. RAW 1장만 기록하며 기존 JSON을 덮어쓰지 않는다.
- `scripts/classify_raw.py`: RAW 또는 `--reg`로 지정한 검토된 REG의 태그에 따른 최초 SFW·NSFW 분류.
- `scripts/assemble_refine.py`: 실행문 대조 함수 `same_input_text`, 신규 REG·REFINE 조립과 기존 형식 읽기. 의존 파일은 `chunk_schema.py`, `library_layout.py`다.
- `scripts/sample_approval.py`: REG·REFINE의 명시적 최종 승인 이미지와 기존 승인 기록 해석.
- `scripts/read_sections.py`: 지정한 문서 절 읽기.
- `scripts/packages.py`: 패키지 구성 조회와 출처·실행 문자열·자체 이미지 검증. 자체 이미지 검증은 `package_gallery.py`를 사용한다.
- `scripts/style_randomizer.py`: 스타일 공통 랜덤 입력문 출력과 선택 전/후 메타데이터 대조.
- `scripts/character_randomizer.py`: 지정 캐릭터의 생성용 포즈·배경 프로필 조립. 갤러리 검증에서 원본 입력과 모든 슬롯의 실제 랜덤 선택 결과를 대조한다.
- `scripts/build_viewer.py`: 샘플과 패키지 JSON에서 오프라인 `library.html` 생성. 화면·구성기 소스는 `viewer/`에 있다.
- `scripts/viewer_groups.py`: [표시 그룹](../viewer/README.md#표시-그룹-저장) 검증과 패키지 기본·변형 구성 묶음.
- `update_html.cmd`: Python 실행 환경을 찾아 HTML을 갱신하는 Windows 실행 파일.

### 작업 범위와 미구현 기능

실행 환경·검사 명령은 [스크립트 안내](../scripts/README.md)를 따른다. REG의 의미 판단·분류·정렬은 [REG 작성 절차](../workflows/reg.md#reg-작성저장전달)에 따라 수행하며 자동 정규화 스크립트는 없다.

HTML의 조회·갱신 범위는 [HTML 안내](../viewer/README.md)를 따른다.

### 스키마와 이전 버전

| 대상 | `schema_version` |
|---|---|
| 신규 REG·REFINE 묶음 | `3` |
| 장면 전체 청크 패키지 | `4` |
| 스타일·캐릭터 패키지 | `3` |

기존 평면 REG, REFINE 1·2, 청크 1~3은 과거 기록으로 읽고 검증한다.

**세부 규칙**

- 과거 기록은 자동 이관·재승인하지 않는다.

## 저장 위치

### 분류와 저장 경로

샘플은 분류와 관계없이 `library/samples/<sample-id>/`에 저장한다. 확정 분류의 정본은 `library/samples/INDEX.MD`의 `분류` 열이다.

신규 RAW 입력에는 전체 샘플에서 미사용인 번호를 부여한다. ID는 `s` 뒤에 번호를 쓰고 네 자리가 되도록 앞에 0을 채운다(`s0001`, `s0002`, …). REG·REFINE 작업과 결과 확인은 같은 샘플을 사용한다.

| 대상 | 경로 | 내용 |
|---|---|---|
| RAW 이미지 | `library/samples/<sample-id>/images/raw.<실제 형식 확장자>` | 메타데이터를 포함한 원본 파일 |
| RAW JSON | `library/samples/<sample-id>/raw.json` | 원본 이미지의 실제 실행값 |
| REG JSON | `library/samples/<sample-id>/reg.json` | 현재 정규화한 실행값과 일치하는 결과 이미지 |
| REG 이미지 | `library/samples/<sample-id>/images/reg.<실제 형식 확장자>` | 첫 REG 결과. 추가 이미지는 `reg-02`부터 미사용 순번 사용 |
| 최종 승인 JSON | `library/samples/<sample-id>/approval.json` | 승인 단계별 기준 이미지와 현재 최종 단계 |
| REFINE JSON | `library/samples/<sample-id>/refine.json` | 현재 묶음별 실행 문자열·연결 순서·기준 설정과 결과 이미지 |
| REFINE 기준 승인 이미지 | `library/samples/<sample-id>/images/refine.<실제 형식 확장자>` | REFINE을 승인한 경우의 기준 이미지 1장 |
| 승인 후 시드 변주 이미지 | `library/samples/<sample-id>/images/refine-variation-01.<실제 형식 확장자>` | 같은 승인 실행에서 seed만 변경한 결과. `01`부터 미사용 순번 사용 |
| REFINE 보관용 대안·비교 이미지 | `library/samples/<sample-id>/images/draft-refine-01.<실제 형식 확장자>` | [보관 대상으로 선택된 비교본](#비교-이미지-보관과-제외). `01`부터 미사용 순번 사용 |

스타일·캐릭터·청크는 SFW/NSFW로 나누지 않고 공유한다. 경로는 `library/styles/<id>.json`, `library/characters/<id>.json`, 신규 장면 청크 `library/chunks/<id>.json`이다. 기존 부분 청크의 `library/chunks/<category>/<id>.json` 경로는 유지한다.

**세부 규칙**

- `sfw`·`nsfw` 하위 폴더를 만들지 않는다. 분류 정정 시 인덱스만 수정하며 샘플 폴더를 이동하지 않는다.
- 분류는 [최초 REG 검토를 포함한 분류 절차](../workflows/reg.md#raw-분류)로 SFW 또는 NSFW를 기록한다. 샘플 안의 모든 단계와 이미지는 같은 폴더에 두고, 이후 REG·REFINE의 태그 변경으로 재분류하지 않는다.
- RAW 실행값이나 별도 JSON에 샘플 분류·오타 목록을 중복 저장하지 않는다.
- 검증기와 HTML은 인덱스의 확정 분류만 읽는다. 분류가 없으면 보류로 표시하고, 잘못된 분류 값이나 분류별 하위 폴더는 오류로 처리한다. RAW 구조·필수 Prompt는 계속 검사하지만 경로·원문 태그로 분류를 추정하거나 재계산하지 않는다.
- `library/samples/INDEX.MD`의 표기는 [샘플 인덱스](#샘플-인덱스)를 따른다.

### 파일 보존과 참조

- 확장자는 파일 헤더로 확인한 실제 형식을 따른다. 원본 바이트는 재인코딩하지 않고 복사한다.
- 기준 이미지 파일명은 [단계별 저장 경로](#분류와-저장-경로)를 따른다.
- JSON의 이미지 경로는 해당 JSON 기준 상대 경로이며 `/`를 사용한다. JSON은 UTF-8, 들여쓰기 2칸으로 저장한다.
- 실행 문자열은 한 벌만 저장한다.

**세부 규칙**

- 기존 파일명을 바꿀 때는 이미지 바이트를 유지하고 JSON·인덱스·패키지의 참조 경로를 함께 갱신한다.
- REG 승인 시 기존 `reg` 이미지 경로를 유지한다. REFINE 승인 시 선택한 원본을 기준 승인 이미지 경로에 저장한다. 이미 보관 중인 `draft-refine`을 선택했다면 이름과 참조를 함께 갱신한다. 기존 기준 승인본은 자동으로 교체하지 않는다.
- 분류용 태그 사본이나 별도 분석·검증 보고서를 추가하지 않는다.
- 패키지 자체 이미지의 경로와 기록은 [패키지 자체 이미지](#패키지-자체-이미지)를 따른다.

## 샘플 인덱스

`library/samples/INDEX.MD` 하나에 `ID | 이름 | 분류 | 상태 | 실행 데이터 | 결과 이미지`를 기록한다. 이름은 인물·장면을 식별할 수 있게 적는다. 상태는 아래 작업 단계 중 하나만 사용한다.

| 상태 | 기준 |
|---|---|
| RAW 접수 | RAW를 받았고 REG 실행문 준비 전 |
| REG 준비 | REG 실행문을 만들었고 생성 결과 확인 전 |
| REG 확인 완료 | 생성된 REG의 실제 실행값 대조·결과 확인 완료 |
| REG 승인 완료 | 사용자가 REG 실행과 결과 이미지를 승인 |
| REFINE 진행 중 | REFINE 구성·생성·피드백 진행 중 |
| REFINE 승인 완료 | 사용자가 REFINE 실행과 결과 이미지를 승인 |

실행 데이터와 결과 이미지는 각각 `RAW` → `REG` → `REFINE` 순서로 있는 항목만 연결한다.

**세부 규칙**

- 상태에 패키지 저장·재사용 여부나 시드 변주 수를 덧붙이지 않는다. 시드 변주를 추가해도 승인 완료 상태는 유지한다.
- 이미지 링크는 단계별 대표 1개만 표시하며, 시드 변주·비교본 목록은 나열하지 않는다.
- REFINE 이미지 링크는 현재 실행에 연결된 기준 승인본만 가리킨다. 승인 전에는 REFINE 실행 데이터만 연결하고 이미지 링크는 생략한다.
- 최종 승인 단계는 `approval.json`을 정본으로 읽는다.
- 시드 변주 이미지와 관찰 기록은 승인 단계의 `reg.json` 또는 `refine.json`의 `images[]`에서 관리한다. 인덱스 표시를 정리할 때 원본 이미지·실행 기록·승인 관계를 변경하지 않는다.

## 실행값과 원본 메타데이터

아래 필드는 RAW의 `images[0]`, REG의 루트, 패키지 자체 이미지의 `execution`에서 같은 의미로 사용한다. 메타데이터의 `Comment`를 JSON으로 해석한 뒤 추출한다.

| 필드 | 자료형·내용 | 원본 |
|---|---|---|
| `base.prompt` | 문자열, BASE Prompt | `v4_prompt.caption.base_caption`; 없으면 `prompt` |
| `base.uc` | 문자열, BASE UC | `v4_negative_prompt.caption.base_caption`; 없으면 `uc` |
| `characters[].prompt` | 문자열, 캐릭터별 Prompt | `v4_prompt.caption.char_captions[].char_caption` |
| `characters[].uc` | 문자열, 같은 순번 캐릭터의 UC | `v4_negative_prompt.caption.char_captions[].char_caption` |
| `characters[].position` | `[{"x": 0.5, "y": 0.5}]` 형태의 좌표 배열 | `v4_prompt.use_coords`가 true일 때 해당 캐릭터의 `centers` |
| `model`, `model_version` | 문자열 | `model_name`(없으면 메타데이터의 `Source`), `model_version` |
| `width`, `height` | 정수, 이미지 크기 | 이미지에서 확인한 실제 가로·세로 |
| `seed`, `steps` | 정수 | 같은 이름의 값 |
| `sampler`, `noise_schedule` | 문자열 | 같은 이름의 값 |
| `scale`, `cfg_rescale` | 수치, Guidance·Guidance Rescale | 같은 이름의 값 |
| `image_to_image` | 객체, 사용된 이미지 변환 설정 | 변환 강도가 활성화된 경우 `strength`, `noise`, `extra_noise_seed` |
| `reference` | 객체, 사용된 참조 설정 | 추출기가 지원하는 참조 강도·정보 추출 설정의 원본 키와 값 |

### 확인된 값과 원본의 보존

- 확인된 값만 기록한다. 미확인 값은 생략한다.
- 캐릭터 배열의 순서와 슬롯 대응을 유지한다.
- 저장 범위는 위 필드다. 추출 범위 밖의 정보는 원본 이미지에 남는다.

**세부 규칙**

- 미확인 값을 `null`·추측값으로 채우지 않는다. 확인된 빈 UC는 `""`이며 미확인 UC와 다르다. 수치 0과 false는 미확인 값으로 취급하지 않는다.
- 캐릭터 슬롯이 없으면 `characters`를 생략한다. REG 작성 전에는 사용하는 모든 슬롯의 Prompt·UC를 확인한다.
- 참조 수치·배열 구조는 그대로 보존한다. 지원 키는 `reference_strength`, `reference_information_extracted`, 이 두 키의 `_multiple` 형태, `director_reference_strength_values`, `director_reference_secondary_strength_values`, `director_reference_information_extracted`다.
- 참조 이미지나 변환 입력 파일의 경로는 메타데이터만으로 복원하지 않는다. 실제 파일을 받은 경우에만 `reference.images`(경로 배열)·`image_to_image.image`(경로 문자열)에 상대 경로로 연결한다.
- 원본 메타데이터 전체 덤프·서명·중복 Prompt를 JSON에 넣지 않는다.

### 랜덤 선택 완료 문자열

랜덤 갤러리의 `execution`은 위 입력 템플릿 대신 `Comment.actual_prompts`의 **선택 완료 문자열**을 사용한다.

**세부 규칙**

- `scripts/style_randomizer.py`의 `read_execution`이 선택 전 입력과 실제 선택 결과를 구분해 반환한다.
- 스타일은 BASE만 허용하며, 캐릭터 프로필 검증은 `allow_characters=True`로 BASE와 캐릭터 Prompt·UC·사용 중인 좌표를 함께 확인한다. 기존 RAW·REG 추출기 동작과 기록은 바꾸지 않는다.
- 원본 메타데이터의 선택 결과가 없거나 불완전하면 추측하지 않는다.

## 자동 프리셋과 실제 실행문

NovelAI의 Quality Tags와 UC Preset은 입력문에 태그를 자동으로 덧붙인다. 프리셋 태그가 포함된 전달문에 자동 태그가 다시 추가되지 않도록 두 설정을 `None`으로 두고 생성하며, 결과에서 재첨가가 의심되면 진행을 중지하고 다시 생성한 이미지를 요청한다.

### 원본 보존과 생성 안내

- RAW에 자동 프리셋이 적용되어 있으면 그 실제 태그도 REG에 명시한다.
- REG·REFINE 생성 안내에는 `Quality Tags: None`, `UC Preset: None`을 모두 명시한다.

### 결과 검사와 중지

1. 결과를 받으면 이미지 메타데이터의 실제 Prompt·UC를 전달한 REG 또는 조립한 REFINE 실행문과 [대조](#실행문-대조)한다.
2. 생성 당시 프리셋 사용이 확인되거나, 전달문에 없던 태그의 추가·중복으로 자동 재첨가가 의심되면 근거와 차이를 알리고 중지한다.
3. 두 설정을 모두 `None`으로 바꾸고 같은 Prompt·UC·seed·생성 설정으로 다시 생성한 원본 이미지를 요청한다.
4. 재요청한 이미지의 실제 실행값을 다시 확인한 뒤 진행한다.

**세부 규칙**

- 2: 중지 대상은 결과 평가·재정제·결과 연결·승인 저장이다.
- 2: 원래 전달문에 있던 중복만으로 판정하지 않으며, 실행문 일치를 UI의 `None` 선택 확인으로 단정하지 않는다.
- 2: 실제 실행값을 읽을 수 없어 대조할 수 없는 경우도 진행하지 않고 확인 가능한 원본을 요청한다.
- 3: 요청 대상은 메타데이터가 포함된 원본 이미지다. 전달한 Prompt·UC와 해당 비교에 안내한 seed·생성 설정을 사용한다.
- 재첨가된 실행문에 맞춰 REG·REFINE을 수정하거나 중복만 삭제해 해당 결과를 정상 실행의 검증으로 연결하지 않는다.
- 일반 실행문 불일치 처리보다 이 중지·재요청 규칙을 우선한다.

### 패키지 이미지에 적용할 때

패키지 대표·서브 이미지에도 두 `None` 설정과 동일한 프리셋 검사·중지 규칙을 적용한다. 대조 대상은 채팅으로 제출한 생성용 전체 실행문이며, 재요청 시 그 요청에서 안내한 설정을 사용한다.

## 실행문 대조

입력 문자열은 다음 표기 차이만 허용해 비교한다.

- 문자열 양끝의 스페이스·탭·개행
- 각 줄의 줄바꿈 직전 스페이스·탭
- 맨 끝 쉼표 한 개의 유무

그 밖의 태그 내부 공백·중간 줄 시작 공백·중간 줄바꿈·태그·중복·가중치·순서·슬롯은 그대로 비교한다.

이미지 결과는 실제 seed·생성 설정이 모두 확인되고 같은 경우에 동일 조건으로 비교한다.

**세부 규칙**

- `scripts/assemble_refine.py`의 `same_input_text`가 이 문자열 비교를 지원한다.
- 허용한 표기 차이만 있으면 중지·재생성을 요구하지 않는다.
- 이 규칙은 비교할 때만 적용한다. RAW·이미지 메타데이터·저장 문자열은 바꾸지 않는다.

## RAW JSON

루트는 `{"images": [실행값]}`이며 RAW 이미지 1개를 기록한다. 실행값에는 `image` 상대 경로와 [실행값 필드](#실행값과-원본-메타데이터)를 둔다. Prompt·UC의 순서·중복·가중치·공백·줄바꿈을 보존한다.

**세부 규칙**

- 추출 스크립트의 출력 구조를 그대로 사용한다.
- REG의 수정 결과를 RAW에 섞지 않는다. 누락된 실행값을 사용자에게 확인해 보완할 때도 실제 원문만 기록한다.

## REG JSON

- 신규 REG는 [묶음 구조](#refine-json)의 `schema_version: 3`으로 스타일·캐릭터·장면 전체 청크 하나를 기록한다.
- 원본의 태그·중복·가중치·슬롯·보호 구문을 보존하면서 정규화한다.
- 설정은 확인된 RAW 값으로 시작하고, `images`는 생성 전 `[]`다.
- 전달하는 입력칸별 문자열은 `execution_record(reg)` 또는 `assemble(reg)`의 조립 결과와 같아야 한다.

**세부 규칙**

- 묶음별 문자열 한 벌만 두고 전체 `base`·`characters` 문자열을 중복 저장하지 않는다.
- RAW 이미지를 REG 결과로 연결하지 않는다.
- 기존 평면 REG(`base`·`characters`)도 그대로 읽는다. 패키징을 위해 묶음 구조로 표현할 때는 변환 전후 전체 실행문·슬롯·좌표·설정 일치를 확인한다. 보존 구문을 나누지 않고 표현할 수 없는 경우 평면 원문을 유지한다.

## 결과 이미지 연결

- [자동 프리셋 검사](#자동-프리셋과-실제-실행문)를 통과하고 [실행문 대조](#실행문-대조) 기준으로 현재 REG의 전체 실행문과 일치하는 이미지만 연결한다.
- `images[]`에는 `image`와 그 이미지에서 확인한 실제 seed·모델·크기·생성 설정을 기록한다.
- REG의 실행 문자열·입력 위치·예정 설정을 수정하면 `images`와 해당 단계의 승인 참조를 해제하고 새 결과로 검증한다.

**세부 규칙**

- 대조 대상은 Prompt·UC·캐릭터 순서·위치이며, 묶음형은 조립 결과와 비교한다. 그 밖의 실행문 차이는 알리고 REG 수정 절차에서 처리한다.
- Prompt·UC·캐릭터 배열은 루트와 중복 저장하지 않는다.
- 설정·seed가 달라도 실행문이 같으면 연결할 수 있으며, 각 결과에서 확인한 실제 값을 기록한다.
- 승인 후 시드 변주에는 선택적 `features`를 기록할 수 있으며 [관찰 요약 기준](#refine-결과-이미지-연결)을 따른다.
- [실행문 대조](#실행문-대조)에서 허용한 표기 차이는 해제 조건의 수정으로 보지 않는다. 해제할 때 기존 RAW와 이미지 파일은 유지한다.

## REFINE JSON

신규 REG와 REFINE은 아래 묶음 구조를 공유한다. REFINE 진행 여부는 [방향 선택](../workflows/refine.md#방향-선택)을 따른다.

| 필드 | 내용 |
|---|---|
| `schema_version` | 신규 묶음 실행은 정수 `3`. 기존 REFINE 1·2는 그대로 읽음 |
| `bundles` | 스타일·캐릭터·장면 전체 청크 배열. 청크는 정확히 하나, `other`는 사용하지 않음 |
| `bundles[].kind` | `style`, `character`, `chunk` |
| `bundles[].name` | 실행 안에서 고유한 이름 |
| `bundles[].slot` | 스타일·캐릭터의 실제 입력 슬롯. 스타일은 `BASE` |
| `bundles[].prompt`, `.uc` | 스타일·캐릭터의 전체 문자열. 빈 값은 `""` |
| `bundles[].roles` | 청크의 역할별 이름·실제 슬롯·Prompt·UC와 선택적 선두 문자열 |
| `bundles[].package` | 연결된 패키지 `{"path": "...", "variant": "base"}`. 선택 필드이며 패키지 연결이 없는 승인 묶음에서도 생략 |
| `positions` | 사용하는 캐릭터 슬롯의 좌표. 사용하지 않으면 생략 |
| seed·모델·크기·설정 | 해당 실행의 확인된 값만 루트에 저장 |
| `images` | 실제 실행과 일치하는 결과 목록. 생성 전 `[]` |

**세부 규칙**

- 신규 청크에는 최상위 `slot`·`prompt`·`uc`·`category`·`subcategory`를 넣지 않는다.
- `base`·`characters` 전체 문자열을 묶음과 중복 저장하지 않는다.

### 문자열 조립

1. 각 슬롯에서 청크 역할에 저장된 `prefix_prompt`·`prefix_uc`를 각각 선두에 둔다.
2. 이후 `bundles` 배열 순서대로 본문 Prompt·UC를 연결한다. 기본 배열은 스타일 → 캐릭터들 → 장면 청크다.
3. 빈 문자열은 건너뛰고 `\n\n`으로 구분한다.

**세부 규칙**

- 선두의 인원·전역 표현도 청크 소유이며, 같은 청크의 본문은 스타일·캐릭터 뒤에 놓일 수 있다.
- 각 문자열은 쉼표로 끝나며, 조립기가 쉼표·태그·가중치를 추가하거나 정규화하지 않는다. 내부 개행과 순서를 그대로 유지한다.
- 기존 REFINE 1·2의 조립은 기존 배열 순서를 유지한다.

### 슬롯과 좌표

캐릭터 슬롯은 `CHARACTER_1`부터 연속되어야 한다. 좌표는 실제 사용 슬롯만 참조한다.

**세부 규칙**

- 역할 연결·슬롯·좌표를 자동 보정하지 않는다.

### 조립 명령

**세부 규칙**

`python -X utf8 -B scripts/assemble_refine.py <reg.json 또는 refine.json>`으로 묶음 실행을 조립한다. 함수 `execution_record`는 기존 평면 REG도 읽는다. 출력은 파생 결과이며 별도 정본으로 저장하지 않는다.

### 청크 역할과 슬롯 연결

- `roles.<키>`의 필수 필드는 `name`, `slot`, `prompt`, `uc`다. 선택 필드 `prefix_prompt`, `prefix_uc`는 같은 슬롯의 선두 표현이다.
- 역할 키는 `scene`, `subject`, `giver`, `receiver` 등 의미 있는 식별자다.
- BASE만, 캐릭터 한 명만, BASE+캐릭터 한 명, 여러 인물의 조합을 허용한다.
- 청크의 선택·제거·교체는 전체 단위다.

**세부 규칙**

- 실제 캐릭터 번호를 역할 키로 쓰지 않는다.
- 같은 청크의 서로 다른 역할은 같은 슬롯을 공유하지 않는다.
- 패키지의 모든 역할을 대상 종류에 맞게 연결한다. 역할 누락·중복·불일치 시 부분 조립하지 않는다.
- 문자열을 바꾼 후보는 기존 패키지와 동일한 참조를 유지하지 않는다.

## 최종 승인 기록

샘플의 `approval.json`은 사용자가 승인한 단계별 기준 이미지와 현재 최종 단계를 가리킨다.

```json
{
  "schema_version": 1,
  "final_stage": "reg",
  "final_image": "images/reg.png",
  "approved_images": {
    "reg": ["images/reg.png"]
  }
}
```

- `final_stage`는 `reg` 또는 `refine`이며 `approved_images`에 반드시 존재해야 한다.
- `approved_images`의 단계별 값은 승인한 이미지 경로 배열이며 중복 없이 보존한다.
- `final_image`는 선택한 단계의 승인 배열에 포함된 경로 하나다.
- 실행을 수정할 때는 그 단계의 `images`와 `approved_images` 참조를 함께 해제한다. 승인본이 없으면 `approval.json`을 제거한다.

**세부 규칙**

- 문자열·설정·이미지를 복제하지 않는다.
- 승인 경로는 해당 단계의 `images[]`에 한 번 연결된 실제 이미지의 샘플 상대 경로다. RAW·비교본·외부 경로는 제외한다.
- 사용자 승인과 실제 실행문·이미지 메타데이터 대조를 마친 뒤에만 작성한다.
- REFINE을 나중에 승인하면 `final_stage`·`final_image`를 지정하고 그 경로를 승인 배열에 추가한다. 이전 REG 실행이 그대로라면 REG 승인 경로도 패키지 출처 근거로 유지할 수 있다.
- 최종 단계가 해제되면 다른 승인본으로의 전환도 명시적으로 결정한다. 잘못된 참조를 다른 이미지로 자동 대체하지 않는다.
- HTML의 샘플 표지·기본 선택은 `final_stage`의 정확한 이미지다. 미승인 REFINE이 추가되어도 승인된 REG를 대체하지 않는다. 승인 전에는 최종 이미지 없이 단계별 자료만 보여준다.
- 기존 자료에 한해 `approval.json`이 없고 인덱스 상태가 `REFINE 승인 완료`이면 REFINE 1·2의 연결 이미지에서 과거 승인본을 읽는다. 이전 기준 이름 `result-refine`이 있으면 그 이름을 우선하고, 없으면 `refine`을 사용한다. 해당 이름의 연결 이미지는 정확히 하나여야 한다. 새 REG·REFINE에는 이 추론을 적용하지 않는다.

## REFINE 결과 이미지 연결

- [자동 프리셋 검사](#자동-프리셋과-실제-실행문)를 통과하고 조립한 실행문과 [대조](#실행문-대조)해 일치하는 결과만 연결한다.
- `images[]`에는 `image`와 실제 seed·모델·크기·생성 설정을 둔다.
- 승인 후 시드 변주에는 선택적으로 `features`를 기록한다. 이미지를 구별하는 구도·포즈·표정 등 관찰 가능한 큰 특징 1~3개를 한 줄의 짧은 한국어 문자열로 적는다. 예: `"낮은 시점의 전신 구도, 상체를 뒤로 젖힌 자세."`
- 묶음 문자열·입력 슬롯·순서·좌표·예정 설정을 수정하면 `images`와 해당 단계의 승인 참조를 해제한다.

**세부 규칙**

- 대조 대상은 Prompt·UC·캐릭터 순서·위치다. 그 밖의 불일치는 먼저 실제 사용할 실행을 확정하고 묶음에 반영한다.
- 묶음·조립 문자열을 `images[]`에 중복 저장하지 않는다.
- `features`에 원인 태그 추정·품질 평가·청크 확정·장문 분석은 넣지 않으며, 뚜렷한 특징을 기록할 수 없으면 필드를 생략한다.
- [실행문 대조](#실행문-대조)에서 허용한 표기 차이는 해제 조건의 수정으로 보지 않는다. 실행 수정만으로 기존 이미지 파일을 삭제하지 않으며, 거절·보관 해제에 따른 처리는 아래 절을 따른다.
- 비교본의 보관·제외는 [비교 이미지 보관과 제외](#비교-이미지-보관과-제외)를 따른다. 승인된 실행과 seed 외 조건이 일치하는 [승인 후 시드 변주](../workflows/refine.md#승인-후-시드-변주)는 해당 절차에 따라 `images`에 추가한다.

### 비교 이미지 보관과 제외

- `draft-refine`은 사용자가 대안·변주·비교용으로 보관을 요청하거나 선택한 이미지에만 사용한다.
- 승인된 실행의 시드 변주는 [시드 변주 이미지 경로](#분류와-저장-경로)와 해당 실행 기록으로 관리한다.
- Prompt·UC가 달라진 대안은 재정제·승인 절차를 따른다.

**세부 규칙**

- 사용자가 거절·폐기하거나 승인을 취소한 결과는 `draft-refine`으로 자동 복사·이동·이름 변경하지 않는다. 원본 보존이나 승인 연결 해제를 이유로 거절본을 우회 보관하지 않는다. 실패 비교용 등 별도 보관을 명시한 경우에만 위 보관 기준을 적용한다.
- 이미 잘못 보관한 사본의 삭제는 사용자가 지정한 파일·범위에 한정한다. 삭제 전 실제 참조를 확인하고, 해당 사본과 참조를 함께 정리한다. 다른 이름의 백업이나 보류 파일로 바꾸어 남기지 않는다.
- 보관용 비교본은 현재 REFINE의 `images`나 패키지 승인 출처에 연결하지 않는다. 각 이미지의 실제 실행값은 원본 메타데이터로 확인하며, 현재 REFINE 실행값을 대신 적용하지 않는다. 인덱스 표시는 [샘플 인덱스](#샘플-인덱스)를 따른다.
- 다른 태그 구성을 현재 승인 실행의 시드 변주로 기록하지 않는다.

## 재사용 패키지 JSON

기본 ID마다 [저장 위치](#저장-위치)의 JSON 한 파일을 사용한다. `variants.base`는 기본본, `variants.v01`부터는 승인된 다른 구성이다. 기본본은 `base`를 유지한다.

| 필드 | 내용 |
|---|---|
| `schema_version` | 스타일·캐릭터는 `3`, 신규 장면 전체 청크는 `4` |
| `id` | 파일명과 같은 기본 ID. 스타일 `stNNN`, 캐릭터 `chNNN`, 청크 `ckNNN` |
| `kind` | `style`, `character`, `chunk` 중 하나 |
| `category` | 기존 부분 청크 2·3에만 지정. 신규 장면 청크에는 금지. [분류 기준](../library/chunks/FORMAT.md#구성과-저장-단위)의 값이며 부모 폴더명과 일치 |
| `subcategory` | 기존 부분 청크 2·3에만 사용. 신규 장면 청크에는 금지. [태그 분류표](prompt_rules.md#대분류와-소분류)의 해당 category 소분류를 소문자로 기록. 같은 ID의 모든 구성에서 공유 |
| `variants` | 구성 키를 속성명으로 갖는 객체. `base` 필수 |
| `variants.<키>.name` | 그 구성의 표시 이름 |
| `variants.<키>.content_rating` | 청크 구성의 `sfw` 또는 `nsfw`. [내용 분류](../library/chunks/FORMAT.md#내용-분류)에 따라 지정. 역할 구조에는 필수, 기존 단일 슬롯 청크는 생략 가능. 스타일·캐릭터에는 두지 않음 |
| `variants.<키>.prompt`, `.uc` | 스타일·캐릭터의 승인된 전체 문자열. 빈 UC는 `""` |
| `variants.<키>.slot` | 스타일만 `BASE`. 캐릭터와 새 청크에는 두지 않음 |
| `variants.<키>.roles` | 새 청크의 역할 객체. 아래 [청크 패키지 역할](#청크-패키지-역할)을 따르며, 구성 최상위에 Prompt·UC·slot을 중복 저장하지 않음 |
| `variants.<키>.sources` | 패키지 태그를 추출·승인한 출처 배열. 각 객체의 `sample`은 승인된 REG 또는 REFINE JSON, `image`는 그 실행에 연결된 승인 이미지 경로. 모두 패키지 JSON 기준 상대 경로. 대표 미지정 시의 [HTML 출처 미리보기](../viewer/README.md#표시-자료와-대표서브)에 사용하며, 자체 대표·서브 등록과 구분 |
| `variants.<키>.gallery` | 해당 구성에 직접 소속된 대표·서브 이미지와 생성 기록. 구조는 [패키지 자체 이미지](#패키지-자체-이미지). 미등록 상태는 `{"images": [], "sub_images": []}` |

### 문자열과 구성 보존

- Prompt·UC의 개행은 JSON 문자열의 `\n`으로 표현하며 실제 문자열의 태그·순서·중복·가중치·공백·개행을 보존한다.
- 각 구성의 전체 Prompt·UC·이름·출처는 독립적으로 보존한다. 청크는 모든 역할의 전체 문자열을 저장한다.
- 새 구성은 [지정한 샘플에서 패키지 등록](../workflows/package_registration.md)에 따라 추가한다.

**세부 규칙**

- 필드는 위 구조를 사용하고, JSON은 UTF-8·들여쓰기 2칸으로 저장한다. 신규 작성 표기는 [표기 규칙](prompt_rules.md#정렬-표기)을 따른다.
- 차이 태그나 기본본 상속으로 저장하지 않는다. 구성의 범위나 태그를 재해석하여 저장하지 않는다.
- 청크의 `content_rating`은 조회용 구성 속성이다. 패키지 루트·역할별·REFINE 묶음에 중복 저장하지 않으며, 샘플 분류나 실제 실행 문자열을 바꾸지 않는다.
- 종류별 판정·저장 기준은 [스타일](../library/styles/FORMAT.md#버전-저장)·[캐릭터](../library/characters/FORMAT.md#바리에이션-저장)·[청크](../library/chunks/FORMAT.md#바리에이션-저장)를 따른다.

### 인덱스와 샘플 연결

- 인덱스는 기본 ID의 JSON 링크와 구성 키를 함께 표시한다.
- 샘플의 `bundles[].package`는 `{"path": "../../characters/ch011.json", "variant": "base"}` 또는 `{"path": "../../chunks/ck050.json", "variant": "base"}`처럼 패키지를 가리킨다.
- `reg.json` 또는 `refine.json`은 해당 단계의 실행 문자열, 패키지 JSON은 재사용 구성의 정본이다.
- `sources`는 RAW→REG→선택적 REFINE에서 추출한 패키지의 근거다.

**세부 규칙**

- 표시 이름을 식별자로 사용하지 않는다.
- 패키지 참조만으로 샘플 문자열을 대체하거나 갱신하지 않는다. 저장·재사용 시 종류·대상 종류와 전체 Prompt·UC를 [실행문 대조](#실행문-대조) 기준으로 확인한다. 캐릭터 슬롯과 청크의 역할별 슬롯은 샘플 실행에서 지정한다.
- 신규 출처는 `approval.json`에 해당 단계와 이미지가 승인되어 있어야 한다. 패키지는 대표 이미지가 없는 상태에서도 저장·재사용할 수 있다. 이미지 등록의 변경 범위는 [패키지 이미지 워크플로우](../workflows/package_images.md#결과-확인과-명시적-선택)를 따른다.

### 청크 패키지 역할

- `roles`는 비어 있지 않은 객체다. 역할 키는 `subject`, `giver`, `receiver`처럼 구성 안에서 고유한 식별자를 쓴다.
- `roles.<역할 키>`는 `name`, `target`, `prompt`, `uc`를 가진다. `name`은 주체·주는 사람·받는 사람 등 표시 이름이며, `target`은 `BASE` 또는 `CHARACTER`다.
- 장면 전체 청크는 필요한 모든 역할을 가진다. BASE 역할은 최대 하나다.

**세부 규칙**

- 캐릭터 번호를 식별자로 쓰지 않으며 실제 캐릭터 번호는 저장하지 않는다. 같은 기본 ID의 구성은 역할 키와 대상 종류를 유지한다.
- 필요한 역할에는 BASE와 캐릭터 한 명의 조합도 포함한다. 필수 Prompt·UC 중 사용하지 않는 쪽은 `""`로 둔다. 선택적 `prefix_prompt`·`prefix_uc`도 역할 안에 저장한다.
- 기존 청크 2·3의 복수 역할 제약은 과거 형식 검증에만 적용한다.
- 역할별 Prompt의 가중치와 검증은 [청크 가중치 규약](../library/chunks/FORMAT.md#가중치)을 따른다. 필요한 가중치는 Prompt 문자열에 포함하고 별도 수치 필드를 만들지 않는다.

### 패키지 조회와 검증

인덱스로 후보를 찾고 필요한 구성만 조회한다. `list`는 구성 키·이름과 기록된 청크 내용 분류를, `show`는 지정 구성의 전체 내용을 출력한다. 실행 명령은 [패키지 조회와 검증](../scripts/README.md#패키지-조회와-검증)을 따른다.

`validate`는 다음을 확인한다.

- 기존·신규 구조의 경로와 전역 ID 중복
- 장면 전체 청크의 루트 경로
- 기존 청크의 category·폴더·subcategory 대응
- 역할 구성과 슬롯 연결
- 출처·샘플 참조와 실행 문자열

**세부 규칙**

- `show`의 기본 구성은 `base`이며, 알 수 없는 구성 키는 오류로 처리한다.
- 샘플 분류와 RAW 구조 검사는 [저장 위치](#저장-위치)의 확정 분류 규칙을 따른다. 출처 샘플에는 해당 구성의 모든 역할이 일치하는 묶음과 연결된 승인 이미지가 있어야 한다.
- 참조 경로는 라이브러리 내부 파일이어야 하며, 명시적 승인 이미지의 메타데이터에서 실제 Prompt·UC·슬롯·좌표와 연결된 설정도 대조한다.
- 위 출처 샘플 검사는 `sources`에 적용한다. `gallery` 이미지에는 샘플 참조를 요구하지 않고 아래 별도 검증을 적용한다.

## 패키지 자체 이미지

### 소유와 저장 위치

- 각 이미지는 한 패키지의 한 구성에 소속된다. 이미지 번호는 해당 구성 안의 `p001`, `p002`, …다.
- 패키지 JSON의 위치는 유지하고, 이미지 원본은 다음 위치에 복사한다. 확장자는 실제 파일 형식을 따른다.

| 소유 패키지 | 이미지 경로 | 패키지 JSON 내부 `image` 예시 |
|---|---|---|
| 스타일 | `library/styles/stNNN/<variant>/images/pNNN.<ext>` | `st001/base/images/p001.png` |
| 캐릭터 | `library/characters/chNNN/<variant>/images/pNNN.<ext>` | `ch001/base/images/p001.png` |
| 장면 청크 | `library/chunks/ckNNN/<variant>/images/pNNN.<ext>` | `ck001/base/images/p001.png` |

- 실제 생성 정보는 소유 패키지 JSON의 `variants.<키>.gallery.images[]`에 둔다.

**세부 규칙**

- 원본 바이트를 재인코딩하지 않는다.
- 자기 패키지나 다른 패키지를 참조하는 경로도 모두 소유 패키지 JSON의 부모 폴더 기준이다. 참조는 라이브러리 내부의 실제 구성으로 제한한다.

### 갤러리 구조

| 필드 | 내용 |
|---|---|
| `gallery.images` | 명시적으로 등록한 이미지의 부속 기록 배열. 이미지 미등록 시 `[]` |
| `gallery.representative` | 대표로 지정한 이미지의 로컬 ID 하나. 미지정 시 필드 생략 |
| `gallery.sub_images` | 서브로 지정한 이미지 ID 배열. 사용자 지정 표시 순서이며 없으면 `[]` |
| `gallery.images[].id` | 구성 안에서 중복되지 않는 이미지 ID, 예: `p001` |
| `gallery.images[].image` | 해당 패키지 JSON 기준 원본 이미지 상대 경로 |
| `gallery.images[].execution` | 이미지에서 확인한 전체 슬롯별 Prompt·UC·좌표와 실제 seed·모델·해상도·생성 설정. [실행값 형식](#실행값과-원본-메타데이터)을 사용하며 내부에 `image`·`images`·`bundles`를 다시 넣지 않음 |
| `gallery.images[].components` | 이 생성에 사용한 기존 패키지 구성과 입력 위치 목록. 조립 순서로 기록하며 아래 구성 연결 형식을 따름 |
| `gallery.images[].user_selection` | 이 이미지의 등록 또는 최근 지정 변경을 승인한 사용자 발언. 대상·용도가 드러나게 실제 대화 근거를 기록하며 승인 문구를 만들어 넣지 않음 |
| `gallery.images[].prompt_template` | 랜덤 생성 프로필 ID. 스타일의 `style-random-vN`은 `formats/style_image_profiles/<ID>.json`, 캐릭터의 `character-chNNN-vN`은 `formats/character_image_profiles/<ID>.json`을 참조. 과거 최소 구성 이미지에서는 생략 |

#### 등록 시점과 표시 참조

- `images`에는 이미지 등록을 승인받은 뒤 기록한다.
- 대표·서브 참조는 같은 구성의 `images[].id`만 가리킨다.
- 지정 해제된 과거 이미지 기록은 원본과 함께 남길 수 있지만, 대표·서브 참조가 없으면 HTML에 노출하지 않는다.

**세부 규칙**

- 생성 전 제안값이나 미선택 후보를 실제 이미지 기록으로 채우지 않는다. 전체 실행문은 `execution` 한 벌에 저장하며 구성별 태그 문자열을 다시 복제하지 않는다.
- 대표를 서브에 중복 노출하지 않으며 서브 ID도 중복하지 않는다. 이미지 배열의 첫 항목·파일명·생성 시각·샘플 승인 순서로 대표를 자동 지정하지 않는다.
- 삭제를 자동 수행하지 않는다.

#### 전체 실행문과 재사용 태그

`execution`은 생성 당시 전체 입력의 기록이다. 패키지 자체 Prompt·UC는 재사용할 부분의 정본이다.

**세부 규칙**

- 원본 이미지·실제 실행값은 생성 후 바꾸지 않는다.
- 전체 생성문에 함께 나온 다른 패키지의 태그나 인원 태그를 소유 패키지 Prompt·UC에 합치지 않는다.
- 참조 구성의 태그가 달라지면 종류별 새 구성 절차를 따른다.

### 구성 연결

`components[]`의 각 항목은 `kind`, `path`, `variant`와 입력 위치를 가진다. `kind`는 `style`, `character`, `chunk`다. `path`는 패키지 JSON 상대 경로, `variant`는 실제 사용한 구성 키다. 자기 패키지도 동일한 방식으로 반드시 포함한다.

#### 공통 연결 규칙

- 스타일·캐릭터 항목은 `slot`을 가진다. 스타일은 `BASE`, 캐릭터는 사용한 `BASE` 또는 `CHARACTER_N`이다.
- 청크 항목은 `roles`에 `{"giver": "CHARACTER_1", "receiver": "CHARACTER_2"}`처럼 모든 역할의 실제 연결 슬롯을 기록한다.
- BASE 인원 태그와 지정한 구성들을 순서대로 연결해 생성용 실행문을 대조한다.
- 이미지 소유자는 이 기록을 가진 구성 하나다.

**세부 규칙**

- 청크 항목에는 최상위 `slot`을 두지 않는다. 역할 키·대상 종류·서로 다른 캐릭터 슬롯의 제약은 [청크 역할](#청크-역할과-슬롯-연결)을 따른다.
- 같은 캐릭터를 여러 슬롯에 사용했다면 항목을 나누어 기록한다. 스타일은 하나, 소유 청크는 하나만 선택하고 관련 없는 청크를 섞지 않는다.
- 스타일·캐릭터와 기존 부분 청크용 실행 인원 태그는 `components` 항목으로 저장하지 않는다. 장면 전체 청크에는 인원 표현이 포함되며 다시 추가하지 않는다.
- 캐릭터 이미지의 실행용 구도는 [캐릭터 생성용 구도](../workflows/package_images.md#캐릭터-생성용-구도)에 따라 같은 첫 묶음에서 검증한다. 구성별 문자열은 [조립 규칙](#refine-json)에 따라 수정 없이 연결한다.
- 필요한 좌표는 `execution.characters[].position`에 실제 값을 보존한다.
- 다른 조합에서 같은 패키지가 사용되어도 그 결과를 해당 패키지 갤러리에 자동 추가하지 않는다.

#### 기본 인물로 생성한 청크 이미지

**세부 규칙**

- 기존 부분 청크에서 [청크 생성용 기본 인물](../workflows/package_images.md#청크-생성용-기본-인물)을 사용한 단일 역할 이미지에는 스타일·청크만 연결한다. 캐릭터 패키지를 만들거나 가짜 참조를 추가하지 않으며, 기본 인물 식별과 선택적인 전신 구도는 해당 규칙에 따라 전체 실행문 대조에 포함한다.

#### 랜덤 템플릿으로 생성한 이미지

**세부 규칙**

- `prompt_template`가 있는 스타일 이미지는 자기 스타일 구성 하나만 연결한다.

  [공통 랜덤 템플릿](../workflows/package_images.md#스타일-공통-랜덤-생성)과 스타일을 조립해 원본의 선택 전 입력을 대조하고, 각 랜덤 구문의 허용 선택 결과만 `execution`으로 인정한다. 스타일 템플릿을 캐릭터·청크 이미지에 사용하지 않는다.
- 캐릭터 템플릿은 [캐릭터 랜덤 구성](../workflows/package_images.md#캐릭터-생성용-포즈배경-랜덤)에 따라 소유 캐릭터 ID·구성 키, BASE 스타일 하나와 CHARACTER_1 캐릭터 하나를 검증한다.

  프로필과 참조 패키지에서 원본 입력 전체를 조립하고 모든 슬롯의 실제 선택 결과를 대조한다.

### 패키지 자체 이미지 검증

`scripts/packages.py validate`는 샘플의 `sources` 검증과 자체 이미지 구조·구성·원본 메타데이터 검증을 구분한다. 사용자 발언과 시각적 적합성, 저장 전후 변경 범위는 작업자가 별도로 확인한다.

**세부 규칙**

1. 패키지 스키마·구성 키, 이미지 ID 고유성, 소유 폴더와 실제 파일·확장자, 상대 경로의 범위를 검사한다. `gallery`에 샘플 참조나 RAW·REG·REFINE 단계 필드를 허용하지 않는다.
2. 대표 ID가 최대 하나이며 실제 등록 이미지인지, 서브 ID의 존재·순서·중복과 대표 중복이 없는지 검사한다. 대표 미지정과 이미지 미등록은 정상 상태다.
3. `components`의 모든 패키지·구성·슬롯·역할을 확인하고 소유 구성이 포함되어 있는지 검사한다. 스타일·캐릭터·청크별 허용 조합은 [생성 구성](../workflows/package_images.md#생성-구성)을 따른다.
4. 실제 전체 Prompt·UC와 캐릭터 순서·좌표를 확인하고, 사용 구성에서 조립한 문자열과 [실행문 대조](#실행문-대조) 기준으로 비교한다. 원본을 읽어 확인한 값과 `execution`이 일치해야 하며, 예정 설정을 실제 값 대신 넣지 않는다.
   - 랜덤 스타일·캐릭터는 템플릿 ID·선택 전 입력·모든 슬롯의 선택 완료 입력·저장된 실제 실행을 모두 대조한다. 패키지 태그 변경, 허용하지 않은 선택지, 추가 태그, 선택 결과 누락은 통과시키지 않는다. 줄 끝 공백 등 허용한 표기 차이만 동일하게 취급한다.
5. 채팅에서 명시적으로 선택한 근거를 확인한다.
6. 이미지 등록·대표 교체·서브 추가가 샘플 인덱스·샘플 파일·패키지 Prompt·UC·`sources`를 변경하지 않는지 검사한다. 저장 후 구현된 HTML 갱신기로 표시를 갱신한다.

## 저장 시 확인

1. JSON 구문, 상대 경로와 실제 파일, 슬롯별 문자열 전체, 캐릭터 순서·위치, seed·설정을 확인한다.
2. 패키지·참조 저장 후에는 [패키지 검증 명령](../scripts/README.md#패키지-조회와-검증)으로 구성과 출처 연결도 확인한다.
3. RAW 원문 보존과 REG의 허용 수정 범위는 별도로 대조한다.
4. 신규 REG·REFINE의 장면 전체 청크와 최종 승인 참조를 확인한다.
5. HTML에 표시되는 샘플·패키지 JSON, 이미지 경로, 샘플 인덱스를 변경했으면 [HTML 갱신](../viewer/README.md#html-갱신)을 수행한다.

**세부 규칙**

- 4: REFINE은 [보존 기준](prompt_rules.md#보존-기준)에 따른 변경 범위, 묶음별 최종 문자열, 슬롯별 조립 결과를 대조하고 [교정 결과](../workflows/refine.md#교정-결과-판단)를 확인한다.
- 5: 문서나 읽기·검색 도구만 수정한 경우에는 갱신하지 않는다.
