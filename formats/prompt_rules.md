# 프롬프트 분류와 배치 규칙

REG·REFINE과 재사용 프롬프트의 공통 분류·배치 기준이다. 분류는 태그의 내용, 입력 슬롯은 적용 대상, 재사용 묶음은 함께 사용할 범위를 나타낸다.

이 문서의 규칙은 새로 작성하는 REG·REFINE·패키지 문자열에 적용한다. RAW 원문, 기존 실행 기록, 기존 승인 패키지에는 적용하지 않으며, 저장된 구성을 재사용·조립·출력할 때도 새 정렬이나 표기 변환을 적용하지 않는다. 패키지 자체 이미지 생성에는 기존 구성의 슬롯 배치·조립 기준을 사용한다.

## 대분류와 소분류

행 순서는 대분류의 기본 순서이며, 각 행의 소분류도 왼쪽부터 적용한다. UC는 Prompt와 별도로 분류한다.

| 대분류 | 소분류 순서 | 분류 범위 |
|---|---|---|
| STYLE | ARTIST → MEDIUM → RENDERING → COLOR → QUALITY → MODIFIER | 작가·매체·렌더링·색감·품질·표현 수식 |
| CHARACTER | IDENTITY → BODY → APPEARANCE → OUTFIT | 인물 식별·체격과 비율·머리와 눈 등 외형·복장과 장신구 |
| POSE | POSTURE → LOWER_BODY → UPPER_BODY → HEAD | 전체 자세·하체·상체와 팔·머리 배치 |
| ACTION | INTERACTION → OBJECT → SOLO | 상대와의 상호작용·물체를 다루는 행동·개별 행동 |
| STATE | EMOTION → EXPRESSION → PHYSICAL | 감정·표정·신체 상태 |
| COMPOSITION | FRAMING → VIEW → PERSPECTIVE → FOCUS | 화면에 담는 범위·보는 방향·원근 표현·초점 |
| SETTING | LOCATION → BACKGROUND → PROP → LIGHTING → ATMOSPHERE | 장소·배경 구성·소품·조명·분위기 |
| EFFECT | MOTION → EMPHASIS → SOUND_FX → TEXT_OVERLAY | 움직임 표현·시각적 강조·효과음·출력 문구 |

소품의 존재·속성은 SETTING.PROP, 소품을 사용하는 행동은 ACTION.OBJECT로 구분한다.

## 의도와 핵심 개념

- 의도는 장면이나 인물에서 표현·유지하려는 방향이다. 인원 수와 구분하며, 태그를 해석하고 보강할 때의 기준으로 삼는다.
- 핵심 개념은 해당 범위의 의미를 대표하는 태그, 구체화 태그(디테일태그)는 그 개념의 조건·특징을 설명하는 표현이다. 같은 태그도 문맥에 따라 역할이 달라진다.
- 범위마다 대표 핵심 개념을 선택적으로 0~1개 둔다.

**세부 규칙**

- 기존에 여러 개념 태그가 있어도 모두 보존하며, 대표 하나를 고르기 위해 다른 태그를 삭제하지 않는다. 빈 범위를 억지로 채우지 않는다.
- 새 표현의 추가는 [REFINE 교정 기준](../workflows/refine.md#방향-선택)을 따르며, 추론한 표현은 채팅에서 밝힌다.

## 입력 슬롯과 재사용 묶음

새 생성 구성을 작성할 때와 [패키지 이미지 생성](../workflows/package_images.md#생성-구성)에 적용한다. REG는 [원본 슬롯과 기존 표현 보존](../workflows/reg.md#목적과-범위)을 우선한다.

| 대상 | 위치와 표기 |
|---|---|
| 전체 인원 태그 | BASE |
| 인물 식별 | Character 슬롯에 숫자 없는 `girl`·`boy`·`other` |
| 원작 캐릭터 | 인물 식별 뒤에 `등록된 캐릭터 태그, 작품 태그` 순서 |
| 스타일 | BASE |
| 캐릭터 | BASE 또는 하나의 Character 슬롯에 통째로 |
| 청크 | [참여 역할](../library/chunks/FORMAT.md#참여-역할)에 따라 각 역할을 지정한 슬롯 |

각 묶음·역할의 Prompt와 관련 UC는 같은 위치의 Prompt와 UC에 각각 배치한다.

원작 캐릭터 예: `girl, chisa (wuthering waves), wuthering waves,` / `girl, remielle dan, zenless zone zero,`.

**세부 규칙**

- REG에서는 위 규칙을 맞추려고 슬롯을 옮기거나 태그를 추가·교체하지 않는다.
- 캐릭터·작품 태그는 [태그 검색](../danbooru-tags/README.md#태그-검색)에서 단부루의 실제 등록 표기를 확인하고 NovelAI 표기 규칙을 적용한다. 등록된 이름에 포함된 괄호는 유지하며, 표면 형식을 통일하려고 임의로 추가·삭제하지 않는다.
- 지정된 슬롯 안에서 재사용 묶음과 각 청크 역할을 연속으로 유지한다. 복수 역할의 슬롯 배치는 역할 연결에 따르며, 정렬 때문에 한 역할을 여러 슬롯에 나누지 않는다.
- 장면 청크의 선두 문자열과 본문 사이에는 같은 슬롯의 스타일·캐릭터 본문이 올 수 있다.

## 정렬 순서

1. BASE 앞부분에는 인원 태그 → 장면 전체의 의도 태그를 둔다.
2. 그 뒤에는 스타일 → 캐릭터 → 장면 청크 본문을 둔다. 나머지 표현은 모두 청크에 포함한다.
3. 각 묶음 안에서는 대분류 → 소분류 순서를 기본으로 적용한다. 없는 분류는 건너뛴다.
4. 대표 핵심 개념은 자신이 대표하는 범위의 첫머리에 둔다.
5. 나머지 구체화 표현은 분류 순서로 배치한다. 분명한 개념·설명 관계가 있으면 개념을 먼저 둔다.

**세부 규칙**

- 1: 특정 인물에게만 해당하는 의도는 그 인물의 묶음에 둔다. 사용 중인 모델의 별도 선두 배치 규칙이 있으면 먼저 적용한다.
- 2: 공통 앞부분은 청크의 `prefix_prompt`·`prefix_uc`로 보관한다. Character의 단수 인물 식별은 해당 캐릭터 묶음의 첫머리에 둔다. 청크는 [장면 전체 하나](../library/chunks/FORMAT.md#구성과-저장-단위)로 유지하고 그 내부에서 분류 순서를 적용한다.
- 4: 여러 소분류를 아우르면 해당 대분류 앞에, 한 소분류 안의 개념이면 그 소분류 앞에 둔다. 여러 대분류를 아우르는 재사용 묶음의 핵심은 그 묶음 앞에 둔다.
- 5: 관계가 없거나 판단이 모호하면 기존 순서를 유지한다.
- 앞에 배치한 태그도 원래 의미 분류를 유지한다.

## 정렬 표기

### 언더바와 쉼표

- 태그의 단어 구분용 언더바(`_`)는 공백으로 변환한다. 예: `long_hair` → `long hair`.
- 각 태그 또는 보호 구문 뒤에 쉼표를 붙인다. 마지막 태그와 묶음 끝도 포함한다.

**세부 규칙**

- 작가명·고유 식별자·이모티콘 등 언더바가 이름이나 표현 자체의 일부이면 일괄 변환하지 않고 NovelAI 표기를 확인한다. 불확실하면 원문을 유지한다.
- 보호 구문 내부에서도 확인된 태그의 단어 구분용 언더바만 변환하며, 가중치 수치·적용 범위·자연어는 보존한다. 쉼표는 구문 바깥에 붙인다.
- 빈 문자열에는 쉼표를 붙이지 않는다.
- 기존 샘플을 재정제할 때는 새 실행문에 적용하고 새 결과로 검증한다. [샘플 최종 승인](../workflows/refine.md#샘플-최종-승인)에 그 실행을 기록한다.

### 줄바꿈

| 구분 | 줄바꿈 |
|---|---|
| 아티스트 태그(STYLE.ARTIST) | 태그마다 한 줄에 두고 개행 1번으로 구분한다. |
| 그 밖의 태그 | 같은 소분류의 태그를 한 줄에 둔다. 소분류 사이는 개행 1번으로 구분한다. |
| 대분류 사이 | 개행 2번(빈 줄 1개)으로 고정한다. |

아티스트 태그 표기 예시:

```text
0.9::artist:morino hon ::,
1.55::artist:kkuem ::,
0.55::artist:bbizim03 ::,
0.35::artist:sumiyao (amam) ::,
0.75::artist:chueog ::,
```

**세부 규칙**

- 아티스트 태그를 감싼 보호 구문도 개별 행에 둔다. 여러 태그를 감싼 가중치 범위 등 보호 구문은 통째로 한 단위로 취급한다.
- STYLE.QUALITY를 포함한 나머지 STYLE 소분류도 "그 밖의 태그" 기준을 따른다.
- 없는 분류는 생략하며, 그 자리에 빈 줄을 추가하지 않는다.
- 보존해야 하는 구문 내부의 줄바꿈은 이 규칙으로 바꾸지 않는다.

### REG 태그 소문자화

REG를 새로 작성하거나 재작성할 때는 모든 입력 슬롯의 Prompt·UC에서 일반·작가·캐릭터 태그의 영문자를 소문자로 통일한다. 예: `artist:Mika Pikazo` → `artist:mika pikazo`.

자연어 문장·이미지에 출력할 문구·대소문자를 구별하는 매크로 이름은 원문을 보존한다.

**세부 규칙**

- 가중치 등 보호 구문 내부의 태그에도 적용한다.
- 프롬프트 전체를 일괄 소문자로 변환하지 않는다.
- 태그와 자연어의 대소문자 구분은 [NovelAI 공식 안내](https://docs.novelai.net/en/faq/#does-capitalization-in-my-text-prompt-matter)를 따른다.

### REG 가중치 구문 정규화

이 절은 REG 작성·저장·전달에만 적용한다.

- 가중치 구문의 닫는 구분자 `::`가 누락되면 복구한다. 예: `3::monochrome` → `3::monochrome ::,`.
- 닫는 구분자 `::` 직전에는 공백 한 칸을 둔다. 숫자로 끝나는 작가명·연도 등이 새로운 가중치 수치로 읽히지 않게 하기 위해서다.
- 여는 구분자는 `0.9::`처럼 가중치 수치에 붙이고, 쉼표는 닫는 구분자 바로 뒤에 둔다.

```text
0.9::artist:morino hon ::,
0.95::artist:koyo2023 ::,
0.85::artist:pigeon666 ::,
::year 2025, year 2026 ::,
-2::multiple views ::,
```

**세부 규칙**

- 닫는 구분자 누락은 문법 오류로 본다. 보호 구문 보존을 이유로 누락 상태를 유지하지 않는다.

## 보존 기준

- REG와 정렬만 수행하는 작업에서는 기존 태그·중복·가중치를 보존한다.
- 나누면 의미가 깨지는 가중치 범위·관계문·랜덤 선택지·자연어는 통째로 처리한다.
- REFINE의 삭제·교체·가중치 변경은 사용자가 지정한 범위에서 처리한다.

**세부 규칙**

- 정렬을 이유로 삭제·교체하거나 핵심 개념 하나로 기존 세부 표현을 대체하지 않는다.
- 분류를 맞추려고 구문을 분해하거나 다른 분류에 복제하지 않는다.
- 새로 구성하거나 재정제하는 REFINE 후보의 중복·충돌·의미 누락은 [교정 결과 판단](../workflows/refine.md#교정-결과-판단)을 따른다.
- 묶음 구성·정렬·패키징의 가중치는 [가중치 규칙](../library/chunks/FORMAT.md#가중치)을 따른다.

## UC 분류

UC는 STYLE → CHARACTER → INTENT 순으로 적용한다.

| 소분류 | 억제 목적 |
|---|---|
| STYLE | 작가·매체·표현 성향과 일반 품질·생성 오류 |
| CHARACTER | 인물의 정체성·외형·체형·복장 변화 |
| INTENT | 그 밖의 자세·행동·상태·구도·환경·효과 변화 |

UC도 기존 표현을 보존한다. 스타일·캐릭터 관련 UC는 해당 묶음에, 나머지 UC 전체는 장면 청크의 해당 역할에 배정한다. 슬롯과 관련 표현의 대응을 유지한다.
