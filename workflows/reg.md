# 1단계 — RAW → REG

RAW 이미지의 프롬프트를 뜻은 그대로 두고 표기만 정리해 REG를 만들고, 같은 조건으로 생성한 결과를 RAW와 비교하는 단계다.

| 순서 | 하는 쪽 | 내용 |
|---|---|---|
| 1 | 사용자 | RAW 이미지를 한 장 또는 여러 장 전달한다. [중요 포인트](#raw-접수-시-중요-포인트)를 함께 말할 수 있다. |
| 2 | 에이전트 | NovelAI 메타데이터를 추출하고 [샘플별 RAW를 등록](#raw-저장과-추출)한다. |
| 3 | 에이전트 | [REG를 작성](#reg-작성저장전달)하고 샘플 분류를 확정한 뒤, 복사해 쓸 입력본을 전달한다. |
| 4 | 사용자 | RAW와 같은 seed·설정으로 REG 이미지를 생성해 전달한다. |
| 5 | 에이전트 | [결과를 확인](#결과-확인)하고 REG 수정, REFINE, 승인 중 다음 단계를 정한다. |

## 목적과 범위

REG는 원문의 의미를 유지하면서 표기를 정규화하고 분류·정렬한 프롬프트다.

| 구분 | 내용 |
|---|---|
| 고치는 것 | 확실한 오타·문법·구분자. 분류·배치·줄바꿈은 [prompt_rules.md](../formats/prompt_rules.md)를 적용한다. |
| 유지하는 것 | 기존 태그·중복·가중치·입력 슬롯·보존 대상 구문 |
| REFINE으로 넘기는 것 | 확인된 충돌이나 중요한 특징의 미구현을 해결하려고 의미를 바꾸는 수정 |

**세부 규칙**

- 접수한 이미지마다 별도 샘플 ID를 부여하고, 각 이미지의 실제 프롬프트·생성 설정으로 `REG 준비`까지 진행한다.
- 분류·정렬은 각 원본 슬롯 안에서 한다. 원문에 없는 인원·의도 태그는 추가하지 않는다.
- 신규 REG의 저장 표현은 스타일·캐릭터와 나머지 전체를 담은 청크 하나다.
- 파일 위치·JSON 필드·결과 연결은 [storage.md](../formats/storage.md)를 따른다.

## RAW 접수 시 중요 포인트

사용자는 RAW 이미지와 함께 이 작업의 목적, 유지할 특징, 허용할 변화를 채팅으로 자유롭게 말할 수 있다. 그림체·캐릭터 요소·포즈·액션·배경 등이 그 예이며, 목적이 여럿이면 우선순위도 함께 받는다.

중요 포인트는 RAW·REG 결과를 비교하고 REFINE 교정이 필요한지 판단하는 기준이다. 말하지 않아도 RAW 접수와 REG 작성은 진행한다.

**세부 규칙**

- 이후 피드백으로 목적이 바뀌면 최신 사용자 의도를 따른다.
- 입력이 없으면, 목적에 따라 선택이 크게 달라지고 판단 근거가 부족할 때만 목적을 확인한다.

## RAW 저장과 추출

1. 원본 이미지의 실제 형식을 확인하고 메타데이터를 읽는다.
2. 원본과 `raw.json`을 샘플별로 등록한다. 여러 장을 함께 받으면 모든 이미지의 추출이 성공한 뒤 등록한다.
3. `raw.json`에서 BASE·캐릭터별 Prompt·UC, 모델·해상도·seed·생성 설정을 확인한다.
4. 읽을 수 없거나 빠진 값은 메타데이터가 남은 원본 또는 실제 입력값을 사용자에게 받아 보완한다.
5. 최초 REG 정규화에서 오타 교정을 검토한 뒤 [샘플 분류](#raw-분류)를 확정해 샘플 인덱스에 기록한다.

**세부 규칙**

- 1: 형식은 파일 헤더로 확인한다. 원본은 수정하지 않는다.
- 2: [저장 위치](../formats/storage.md#저장-위치)를 따른다. 아래 명령을 패키지 루트에서 실행한다.

  `<sample-id>`는 미사용 ID, `<ext>`는 실제 형식의 확장자(`png` 또는 `webp`)다.

  ```text
  python -B scripts/extract_metadata.py "library/samples/<sample-id>/images/raw.<ext>" --out "library/samples/<sample-id>/raw.json"
  ```
- 2: 여러 장은 `library/samples/` 대신 요청 전용 임시 폴더에 같은 하위 경로로 원본을 복사하고 위 명령을 이미지마다 실행한다. 전부 성공하면 준비한 샘플 폴더들을 `library/samples/`에 반영한다.
- 2: 일괄 접수 중 한 장이라도 NovelAI 메타데이터 추출에 실패하면 이번 요청의 임시 작업분 전체를 폐기한다. 샘플·인덱스·HTML에 변경을 남기지 않고, 실패한 원본 파일명과 사유, 등록 0건을 알린다. 원본을 보완하면 요청 전체를 다시 검사한다.
- 3: [RAW JSON](../formats/storage.md#raw-json)의 `images[0]`에서 확인한다.
- 4: 단건 접수에서는 읽을 수 없는 이미지 형식·메타데이터와 누락된 실행값을 보완한다. 일괄 접수에서는 전체 추출 성공 후 확인된 누락값에만 이 단계를 적용한다.

### 추출 도구와 실행 준비

**세부 규칙**

추출 스크립트 `scripts/extract_metadata.py`는 Python 3.10 이상에서 파일 헤더로 PNG·WebP를 구분한다.

PNG는 표준 라이브러리로 텍스트 메타데이터와 8비트 RGBA·GA 비인터레이스 알파 채널을 읽으며, Comment 텍스트를 우선한다. 정지 WebP는 Pillow로 알파 채널을 읽는다.

두 형식의 알파 채널에서 `stealth_pngcomp`·`stealth_pnginfo`를 지원한다. WebP의 EXIF·XMP 추출은 범위 밖이다.

의존성 설치는 [실행 환경 준비](../scripts/README.md#실행-환경-준비)를 따른다.

### RAW 분류

프롬프트에 `nsfw` 또는 `sex` 태그가 하나라도 있으면 `nsfw`, 둘 다 없으면 `sfw`다. 분류는 최초 REG 검토에서 한 번 확정해 `library/samples/INDEX.MD`의 `분류` 열에 기록한다.

오타가 명백하면 교정한 태그로 분류한다. 작가명·캐릭터명처럼 교정하면 뜻이 달라질 수 있는 경우는 사용자에게 확인한다.

**세부 규칙**

- 검사 대상: 검토한 REG가 있으면 전체 실행문(묶음형은 조립한 `base.prompt`·`characters[].prompt`)을 검사하고, 교정이 없으면 RAW의 같은 슬롯을 검사한다. BASE·캐릭터 UC, 파일명, 이미지 관찰 결과는 분류에 사용하지 않는다.
- 태그 비교: 대소문자는 구별하지 않고 쉼표로 구분된 태그의 양끝 공백과 가중치 표기를 제외해 태그 전체를 비교한다. `sexy`·`unisex`·`sex scene` 같은 다른 문자열은 일치로 보지 않는다.
- 가중치: 부호·수치와 관계없이 태그가 있으면 포함한다. `1.2::nsfw::`와 `-1::nsfw::`는 모두 NSFW다. 여러 태그를 감싼 가중치 범위 안에서도 각 태그를 검사한다.
- 오타 교정: RAW 원문은 보존하고, 의미를 유지하는 명백한 오타 교정은 REG에 반영한다.
- 확인 도구: `python -X utf8 -B scripts/classify_raw.py <raw.json>`은 RAW 원문 기준 결과를 출력한다. 오타 교정을 검토한 REG가 있으면 `python -X utf8 -B scripts/classify_raw.py <raw.json> --reg <reg.json>`으로 확정할 결과를 확인한다. 메모리에 있는 후보는 `classify_raw(raw_record, reg=reviewed_reg)`로 같은 검사를 할 수 있다. 오타의 의미 보존 여부는 REG 검토에서 판단한다.
- 보류: RAW 또는 분류에 사용하는 REG의 Prompt가 누락되었거나 읽을 수 없으면 분류를 보류하고 원본·실제 입력값을 확인한다. 확인된 빈 Prompt와 미확인 Prompt를 구별한다.
- 재분류: 이후 REG·REFINE의 태그 변경이나 HTML 갱신 때 재분류하지 않는다.
- 저장 경로와 이후 단계의 취급은 [저장 위치](../formats/storage.md#저장-위치)를 따른다.

## REG 작성·저장·전달

1. 원문 전체를 분류하고 허용한 표기 정규화·정렬을 적용한다.
2. RAW와 대조해 허용한 표기 수정 외에 바뀐 것이 없는지 확인한다.
3. `reg.json`을 저장한다.
4. 슬롯별 Prompt·UC, RAW 기준 seed, 생성 설정, 주요 수정 내용, RAW 이미지와 RAW·REG JSON 링크를 전달한다.
5. RAW와 같은 seed·설정으로 첫 REG 이미지를 생성하도록 안내한다.

사용자는 다른 seed로 추가 이미지를 생성해 특징이 유지되는지 볼 수 있고, 결과 이미지와 함께 RAW 대비 중요한 차이나 보완 희망 사항을 전달할 수 있다. 둘 다 선택 사항이다.

**세부 규칙**

- 1: 뜻이 불확실한 표현은 유지하며, 분리하면 의미가 깨지는 구문은 통째로 처리한다.
- 2: 확인 대상은 태그·중복·가중치·입력 슬롯이다.
- 3: [REG JSON](../formats/storage.md#reg-json)을 따른다. 생성 전 결과 목록은 비워 둔다.
- 4: Prompt·UC는 저장한 REG에서 조립한 슬롯별 전체를 각각 복사 가능한 코드 블록으로 전달한다. 슬롯명·설명은 코드 블록 밖에 둔다. seed는 `raw.json`의 `images[0].seed`를 **RAW 기준 seed**로 코드 블록 밖에 표시한다.
- 4: 여러 장을 등록하면 원본 파일명·샘플 ID·처리 상태를 한 표로 정리하고, 준비된 REG 입력본을 샘플 ID별로 전달한다.
- 5: [자동 프리셋 규칙](../formats/storage.md#자동-프리셋과-실제-실행문)의 두 `None` 설정을 명시한다. 위의 두 선택 사항도 함께 안내한다.

## 결과 확인

사용자가 REG로 생성한 이미지와 선택적인 비교 피드백을 받아, 사용자가 중요하게 보는 RAW·REG의 차이와 보완할 사항을 정리한다.

1. 결과 이미지의 실행값을 읽어 `reg.json`·RAW와 대조한다.
2. 자동 프리셋 검사의 중지 조건이면 이미지를 다시 요청하고 이후 절차로 넘어가지 않는다.
3. 검사를 통과한 뒤 남은 실제 실행문·캐릭터 슬롯 차이는 사용자에게 알리고 [REG 작성 절차](#reg-작성저장전달)에서 처리한다.
4. 실행문이 일치하면 이미지를 샘플에 복사하고 `reg.json`에 결과를 연결한다.
5. 중요 포인트와 사용자 피드백을 기준으로 중요한 차이, 유지할 특징, 허용할 변화, 보완할 사항을 정리한다.
6. 다음 단계를 정한다.

| 판단 | 다음 단계 |
|---|---|
| REG 범위의 문제 | 같은 `reg.json`을 수정하고 완성본을 다시 전달한다. |
| 명확한 충돌 또는 중요한 특징의 미구현 | 해당 문제를 [선택적 REFINE](refine.md#방향-선택)으로 전달한다. |
| 교정 불필요 | 사용자가 REG 실행과 결과 이미지를 명시적으로 승인하면 [샘플 최종 승인](refine.md#샘플-최종-승인)으로 마친다. |

**세부 규칙**

- 1: 스크립트의 `extract(이미지 경로, 샘플 폴더)` 함수를 사용한다. 함수는 값을 반환하며 파일을 쓰지 않는다.
- 2: [자동 프리셋 검사](../formats/storage.md#자동-프리셋과-실제-실행문)를 다른 대조보다 먼저 적용한다.
- 3: 전달된 실제 결과를 기준으로 REFINE을 진행할 때는 실제 실행값을 REG에 반영한 뒤 결과를 연결한다.
- 4: [결과 이미지 연결](../formats/storage.md#결과-이미지-연결)에 따라 `reg.json`의 `images`에 실제 값을 반영한다. 비교 조건은 [실행문 대조](../formats/storage.md#실행문-대조)를 따른다.
- 5: 기준은 [중요 포인트](#raw-접수-시-중요-포인트)다. 피드백이 없으면 관찰한 차이와 해석을 구별해 설명한다. 정규화 규칙의 준수와 핵심 특징의 유지 여부를 함께 평가한다.
- 6: 큰 차이가 있으면 표기 수정·재배열과 실제 실행값부터 점검한다. REG를 수정하면 결과 연결을 비운다.
