# 선택 단계 — REFINE

REFINE은 REG 결과의 문제를 교정하는 선택 단계다. 진행 여부는 [방향 선택](#방향-선택)에서 판단한다.

| 순서 | 하는 쪽 | 내용 |
|---|---|---|
| 1 | 에이전트 | RAW·REG 기록, REG 이미지, 사용자 피드백을 [비교](#입력과-비교)한다. |
| 2 | 에이전트 | 교정이 필요한지 [판단](#방향-선택)한다. 필요 없으면 REG 승인으로 진행한다. |
| 3 | 에이전트 | 필요한 부분만 [교정](#묶음-구성과-교정)하고 [REFINE 세트](#refine-세트-출력)를 전달한다. |
| 4 | 사용자 | 기준과 같은 seed·설정으로 [생성](#최초-제안과-생성)해 결과를 전달한다. |
| 5 | 에이전트·사용자 | [결과를 확인](#피드백과-승인)한다. 보완이 필요하면 3으로 돌아가고, 문제가 없으면 사용자가 승인한다. |
| 6 | 에이전트 | [샘플 최종 승인](#샘플-최종-승인)을 기록하고 샘플 작업을 마친다. |
| 승인 후 | 사용자 | 승인 실행에서 seed만 바꾼 결과를 전달하면 [시드 변주](#승인-후-시드-변주)로 기록한다. |

## 용어

추상화태그·핵심태그·디테일태그는 표현을 이해하는 문맥상 역할이다.

## 입력과 비교

1. RAW와 REG 실행 기록, 실제 REG 이미지, 사용자가 밝힌 유지할 특징과 피드백을 확인한다.
2. [REG 결과 확인](reg.md#결과-확인)에 따라 실제 실행값을 대조한다.
3. 원문의 의미를 유지하는 정규화 오류는 REG에서 바로잡는다. 의미 변경이 필요한 문제만 [방향 선택](#방향-선택)의 기준으로 REFINE 대상인지 판단한다.

**세부 규칙**

- 2: 대조 대상은 자동 프리셋, Prompt·UC·슬롯·좌표·seed·설정이다.

## 방향 선택

| 판단 | 조건 | 처리 |
|---|---|---|
| 충돌 교정 | 같은 대상·슬롯·문맥에서 의도를 방해하는 상반된 표현이나 Prompt·UC의 충돌이 확인됐다. | 관련 부분만 수정한다. |
| 중요한 특징의 미구현 교정 | 사용자가 유지하려던 자세·표정·관계 등이 결과에서 구현되지 않았다. | 관련 표현만 수정한다. |
| 교정 불필요 | 위 두 경우가 아니다. | 태그·중복·가중치를 유지하고 REG 승인으로 진행한다. |

목적이 모호하면 그 문제에 한해 사용자에게 확인한다.

**세부 규칙**

- 충돌 교정: 단어가 반대라는 이유만으로 다른 대상·조건의 표현을 충돌로 단정하지 않는다.
- 미구현 교정: 그림 한 장에서 보이지 않는 태그를 무효·불필요하다고 판단해 삭제하지 않는다.
- 교정 불필요: REFINE 파일을 만들지 않는다.

## 묶음 구성과 교정

1. 스타일·캐릭터들과 나머지 전체를 담는 청크 하나로 구성한다.
2. 교정할 문제, 유지할 특징, 변경할 표현과 이유를 사용자에게 짧게 설명한다.
3. 해결에 필요한 최소한의 태그 추가·교체·삭제·UC 조정·가중치 변경만 수행한다.
4. 추가·대체할 태그가 필요하면 태그 검색으로 찾는다.

**세부 규칙**

- 1: [청크 규약](../library/chunks/FORMAT.md#구성과-저장-단위)을 따른다.
- 2: 이미지 관찰·원문 표현·추론을 구분한다.
- 3: 의미·가중치·보호 구문·슬롯은 변경 대상으로 특정한 부분 외에는 유지한다.
- 4: 추가·대체 태그가 필요할 때만 [태그 검색](../danbooru-tags/README.md#태그-검색)에 따라 찾는다. 적합한 태그가 없으면 짧은 자연어를 사용하고 추론한 표현임을 밝힌다.
- 저장 구조: 새로 구성한 실행은 [REG·REFINE 묶음 구조](../formats/storage.md#refine-json)를 사용한다.
- 패키지 참조: 교정으로 기존 패키지와 문자열이 달라진 묶음은 수정본에서 해당 참조를 해제한다.

### 교정 결과 판단

확인된 충돌이나 중요한 특징의 미구현이 남아 있으면 사용자 피드백에 따라 해당 부분을 더 교정하거나 그 차이를 허용할지 정한다.

**세부 규칙**

- 의미가 명확한 범위의 교정은 개별 확인 없이 수행하고, 의도가 모호하면 확인한다.
- 최종 실행과 필요한 승인 근거만 저장한다.

## 묶음별 저장과 조립

신규 REG와 REFINE은 같은 묶음 구조로 저장한다. 실행할 때는 묶음을 슬롯별로 이어 붙여 전체 Prompt·UC를 만든다.

| 묶음 | 들어가는 슬롯 |
|---|---|
| 스타일 | BASE |
| 캐릭터 | 원래 적용 슬롯 |
| 청크 | 역할별 슬롯 |

**세부 규칙**

- 같은 슬롯의 Prompt와 UC에 각각 대응시킨다.
- 청크의 선두 문자열을 먼저 배치하고, 본문은 묶음 배열 순서로 연결한다. 인원·전역 의도도 청크 내부의 선두 필드에 둔다. 상세는 [문자열 조립](../formats/storage.md#문자열-조립)을 따른다.
- 조립 시 태그·가중치·내부 개행을 재정렬하거나 변환하지 않는다. 전체 슬롯 문자열을 묶음과 중복 저장하지 않는다.

## REFINE 세트 출력

REFINE 세트는 사용자가 NovelAI에 입력할 교정본이다. 다음 순서로 출력한다.

1. 교정 대상과 변경 이유, 기준 seed·설정
2. 스타일·캐릭터·청크의 Prompt·UC와 역할별 입력 위치
3. 조립한 최신 전체 BASE·캐릭터별 Prompt·UC

**세부 규칙**

- 1: `Quality Tags: None`·`UC Preset: None`을 안내한다.
- 2: 청크의 선두와 본문도 모두 포함한다. 재정제 때는 바뀐 묶음의 전문과 이유만 반복하고, 변경하지 않은 묶음 설명은 생략한다.
- 3: 마지막에 둔다. 2와 같은 저장 데이터에서 조립하고 입력칸마다 별도 코드 블록으로 출력한다. 빈 칸은 `비움`으로 표시한다.

## 최초 제안과 생성

REFINE 세트를 전달하면 사용자는 기준과 같은 seed·설정으로 교정 결과를 생성한다. 추가 seed는 선택 사항이다.

**세부 규칙**

- 생성 전에 별도 승인 단계를 추가하지 않는다.
- 비교 조건은 [실행문 대조](../formats/storage.md#실행문-대조)를 따른다.

## 피드백과 승인

1. 실제 이미지의 실행값을 현재 실행과 대조한다.
2. 특정한 문제가 해결됐는지와 유지할 특징이 보존됐는지를 확인한다.
3. 보완이 필요하면 관련 부분을 재교정한다. 문제가 없으면 사용자 승인을 받는다.

교정하지 않은 REG도 같은 방식으로 승인받아 최종본으로 선택할 수 있다.

**세부 규칙**

- 1: 대조 대상은 Prompt·UC·슬롯·좌표·seed·설정이다. [자동 프리셋 검사](../formats/storage.md#자동-프리셋과-실제-실행문)의 중지 조건을 우선 적용한다.
- 승인: REG와 REFINE 모두 실제 실행과 결과 이미지에 대한 사용자의 명시적 승인이 필요하다. 승인 단계는 파일 존재나 생성 시각으로 추측하지 않는다.

## 샘플 최종 승인

에이전트는 사용자가 승인한 단계와 기준 이미지를 `approval.json`에 기록하고 [샘플 인덱스](../formats/storage.md#샘플-인덱스)를 갱신하면 샘플 작업을 마친다. 스타일·캐릭터·청크 묶음은 샘플 안에 실행 기록으로 보존한다. 라이브러리에 재사용할 구성을 저장하는 절차는 [지정한 패키지 등록](package_registration.md)에서 다룬다.

| 승인 대상 | 기준 이미지 |
|---|---|
| REG | 기존 `reg` 이미지를 그대로 사용한다. |
| REFINE | 해당 실행에 연결된 기준 이미지를 사용한다. |

실행을 수정하면 그 단계의 이미지 연결과 승인 참조를 해제한다.

**세부 규칙**

- [최종 승인 기록](../formats/storage.md#최종-승인-기록)에 단계와 이미지 경로를 기록한다.
- 이전 단계의 승인 출처는 해당 실행이 그대로인 동안 보존할 수 있다.

## 승인 후 시드 변주

최종 승인된 REG 또는 REFINE의 동일 실행에서 seed만 바꾼 추가 결과를 사용자가 전달했을 때 진행한다.

1. 각 이미지의 실행값이 seed 외에는 승인 단계와 같은지 확인한다. 다르거나 확인할 수 없으면 기록을 중지한다.
2. 해당 단계의 이미지 목록에 연결한다. 기존 최종 승인 이미지 선택은 유지한다.
3. 관찰 가능한 큰 특징 1~3개를 선택적으로 기록한다.

**세부 규칙**

- 1: 각 원본의 실제 실행문·슬롯·좌표를 승인 단계와 대조하고 seed 외 설정도 확인한다. 자동 프리셋 검사 중지 조건도 기록 중지 사유다.
- 2: `images[]`에 실제 설정과 함께 연결한다. 파일명과 시작 번호는 [단계별 저장 경로](../formats/storage.md#분류와-저장-경로)를 따른다.
- 3: 선택적 `features`에 기록한다. 원인 태그 추측·품질 평가·새 청크 판정을 넣지 않는다.
