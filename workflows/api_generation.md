# 선택적 API 생성

기본 생성 경로는 사용자가 NovelAI에서 이미지를 생성해 전달하는 방식이다. 사용자가 해당 작업의 프롬프트에서 NovelAI API 사용을 명시적으로 지시한 경우에만 에이전트가 API로 생성과 결과 수신을 수행한다.

이 문서는 REG·REFINE·패키지 이미지 워크플로우의 사용자가 이미지를 생성해 전달하는 단계를 대신한다. 생성 전 준비와 결과 확인 이후 절차는 해당 워크플로우를 따른다.

1. 해당 워크플로우에서 준비한 최종 실행문과 생성 설정을 확인한다.
2. API 도구로 이미지를 한 장씩 순차 생성하고 메타데이터가 포함된 원본을 확보한다.
3. 해당 워크플로우의 결과 확인 절차로 돌아가 검증·비교·보고한다.

**세부 규칙**

- 1: “API로 REG 이미지를 생성해 줘”처럼 API 사용 지시가 있어야 한다. API 키 설정, API 관련 질문, 과거 작업의 API 사용 이력은 현재 작업의 API 생성 지시로 간주하지 않는다.
- 1: 지시는 요청한 대상과 작업 범위에 적용한다. 같은 요청에 포함된 여러 이미지에 대해 매번 지시를 다시 받지는 않는다. 새로운 작업에는 이전 작업의 API 사용 지시를 자동 적용하지 않는다.
- 1: 도구가 실제 지원하는 입력과 설정에만 적용한다. 지원하지 않는 값을 임의로 생략하거나 다른 값으로 바꾸지 않는다.
- 2: 여러 샘플이나 시드를 작업할 때 API 호출 하나당 이미지 한 장을 요청한다. 서로 다른 `generate`·`resume` 실행에도 같은 순서를 적용한다. 앞 요청의 원본 저장과 메타데이터 검증이 끝났거나 실패·불명 상태가 기록된 뒤에 다음 요청을 제출한다.
- 2: 요청한 장수·시드·설정만 실행한다. 실패하거나 결과 수신 여부가 불명확하면 상태를 보고하고 자동 재전송하지 않는다.
- 3: 요청값을 실제 생성값으로 간주하지 않는다. [자동 프리셋 검사](../formats/storage.md#자동-프리셋과-실제-실행문)와 [실행문 대조](../formats/storage.md#실행문-대조)를 반환 원본에 적용한다.
- 3: 결과 연결·보존 위치·최종 승인·패키지 등록은 해당 워크플로우와 [저장 규약](../formats/storage.md)을 따른다. 시각적 비교와 보고는 에이전트가 이미지를 열어 수행한다.

## 도구와 지원 범위

구현은 `scripts/novelai_api/`, Windows 실행기는 `scripts/novelai_api.ps1`이다. 아래 명령은 프로젝트 루트에서 실행한다. 명령별 옵션은 `--help`로 확인한다.

1. 저장된 REG·REFINE 또는 전체 실행 JSON과 기준 원본을 읽는다.
2. 지원 모델의 텍스트 기반 이미지 생성과 결과 메타데이터 검증을 수행한다.
3. 검토한 REG는 기존 샘플에 연결하고, 다른 용도의 결과는 원본 파일로 내보낸다.

**세부 규칙**

- 1: Python 3.10 이상과 기존 `scripts/requirements.txt`의 Pillow를 사용한다. 원문 정규화는 기존 REG 작성 절차에서 수행하며 도구가 태그를 교정하지 않는다. 전체 슬롯 조립은 `assemble_refine.py`를 재사용한다.
- 1: 기본 기준 원본은 같은 샘플의 `raw.json`에서 찾는다. 별도 실행 JSON은 `--baseline`으로 기준 원본을 지정한다. 모든 입력은 프로젝트 루트 내부에 있어야 한다.
- 2: V4 Full·Curated Preview, V4.5 Full·Curated, V5 Full·Curated의 일반 생성과 캐릭터 슬롯·좌표를 지원한다. 모델은 원본의 확인된 해시로 결정하며, 확인되지 않으면 `--model` 지정이 필요하다. Medium Effort, 참조·img2img·인페인트·업스케일·SMEA·랜덤 프롬프트·사용자 추가 연산 설정은 지원하지 않는다.
- 2: 확인된 원본 설정으로 시작하고 REG·REFINE에 저장된 설정을 우선한다. 첫 비교의 RAW 조건 일치 여부를 `plan`에서 확인한다. 프리셋 자동 추가는 끄며, 반환 문자열과 설정을 다시 검증한다. 명시한 시드별로 한 장씩 순차 요청하며 한 실행은 최대 16장이다.
- 3: 자동 연결 명령은 REG만 지원한다. REFINE 승인·패키지 갤러리 등록·대표 지정은 기존 워크플로우로 진행한다. `export`는 파일 복사이며 승인이나 갤러리 등록을 수행하지 않는다.

## 실행 명령

1. 키 설정을 확인한다.
2. 입력과 생성 설정을 사전 점검한다.
3. API 사용 지시 범위에 맞게 생성하고 결과를 확인한다.
4. 시각적 검토 후 결과를 연결하거나 내보낸다.

**세부 규칙**

- 1: `./scripts/novelai_api.ps1 doctor`는 네트워크 없이 키 존재·설정 위치만 확인한다. 프로세스 환경변수, Windows 사용자 환경변수 순서로 `NOVELAI_API_KEY`를 읽으며 키 내용은 출력하지 않는다. 인증 유효성만 확인하려면 `doctor --remote`를 사용한다. 이는 이미지 생성 없이 구독 조회 GET을 호출한다.
- 2: `./scripts/novelai_api.ps1 plan library/samples/s0001/reg.json`은 파일 저장이나 API 호출 없이 점검한다. 필요한 경우 `--model <API 모델 ID>`, `--baseline <원본 경로>`, `--seeds 123 456`을 지정한다. 전체 요청은 `--show-payload`로 확인할 수 있다.
- 3: `./scripts/novelai_api.ps1 generate library/samples/s0001/reg.json --api`로 기준 시드 한 장을 생성한다. `--seeds 123 456`을 추가하면 그 두 시드만 생성한다. `--api`는 해당 작업의 API 사용 지시를 실행 명령에 반영하는 플래그다.
- 3: `./scripts/novelai_api.ps1 inspect runs/novelai/<실행 ID>`는 네트워크 없이 반환 원본을 다시 검증하고 저장된 이미지가 있는 중단 항목을 복구한다. `resume runs/novelai/<실행 ID> --api`는 아직 제출하지 않은 항목만 이어서 실행하며 실패·불명 항목을 재전송하지 않는다.
- 4: RAW와 결과를 실제로 열어 비교한 뒤 `attach-reg runs/novelai/<실행 ID> --image 1 --reviewed`를 실행한다. `--reviewed`는 시각적 비교 완료 표시이며 최종 승인 표시가 아니다. 기존 샘플의 REG 결과 연결·인덱스·HTML을 갱신한다. HTML 갱신 실패 시 연결은 보존되며 같은 명령을 다시 실행할 수 있다.
- 4: `export runs/novelai/<실행 ID> --image 1 --to <목적 이미지 경로>`는 원본 바이트를 그대로 복사한다. 목적 파일이 다른 내용으로 이미 존재하면 중지한다. 패키지 목적지와 등록은 [패키지 이미지 절차](package_images.md#결과-확인과-명시적-선택)를 따른다.
- 실행기 대신 `python -X utf8 -B scripts/novelai_api <명령>`을 사용할 수 있다. 실행기를 위한 Python 경로를 직접 지정하려면 `NOVELAI_PYTHON` 환경변수를 사용한다.

## REFINE 태그로 생성·전달

1. [REFINE 세트](refine.md#refine-세트-출력)로 준비한 최신 교정본을 입력으로 선택한다.
2. REFINE 태그로 이미지를 생성하고 원본을 확보한다.
3. [결과 확인 절차](refine.md#피드백과-승인)에 따라 교정 전 결과와 비교해 문제의 해결 여부와 유지할 특징을 확인한다.
4. 결과 이미지를 사용한 REFINE 기록·seed·생성 설정·비교 의견과 함께 채팅으로 전달한다.

**세부 규칙**

- 1: 입력은 해당 샘플의 `library/samples/<sample-id>/refine.json`이다. 슬롯별 전체 Prompt·UC는 [묶음 조립 규칙](refine.md#묶음별-저장과-조립)을 따른다.
- 2: `./scripts/novelai_api.ps1 plan library/samples/<sample-id>/refine.json`으로 사전 점검한 뒤, `./scripts/novelai_api.ps1 generate library/samples/<sample-id>/refine.json --api`로 생성한다. 비교 조건은 [최초 제안과 생성](refine.md#최초-제안과-생성)을 따른다.
- 3: 첫 교정 결과는 REG와, 재교정 결과는 교정 대상이 된 직전 REFINE과 비교한다. RAW에서 유지할 특징도 함께 확인한다.
- 4: 보존·결과 연결은 [REFINE 결과 이미지 연결](../formats/storage.md#refine-결과-이미지-연결), 결과 승인은 [샘플 최종 승인](refine.md#샘플-최종-승인)을 따른다.

## 생성 작업본

실행별 원본 이미지와 최소 처리 상태는 `runs/novelai/<실행 ID>/`에 둔다. 검증·시각적 검토를 마친 결과는 기존 샘플 또는 선택한 목적지로 복사하며, 작업본은 재개와 중복 방지에 사용한다.

**세부 규칙**

- `manifest.json`에는 출처·기준 원본 경로, 요청 모델·시드·이미지 형식(`image_format`), 실행 지문, 파일 해시, 처리 상태와 등록·내보내기 경로만 기록한다. 키·인증 헤더·중복 프롬프트·별도 분석 보고서를 저장하지 않는다.
- 신규 API 이미지 생성 요청은 `parameters.image_format`을 `"webp"`로 지정한다. 기존 실행을 재개할 때는 최초 요청의 형식을 유지한다.
- 반환 원본은 파일 헤더에서 확인한 형식으로 저장한다. WebP는 `image-001.webp`, PNG는 `image-001.png`처럼 기록한다. 재인코딩·기존 파일 덮어쓰기·작업본 자동 삭제를 하지 않는다.
- `planned` → `submitted` → `received` → `validated`는 기계 검증 상태다. `unknown`은 생성 여부 불명, `failed`는 HTTP 실패, `rejected`는 저장·검증 실패다. 이 상태들은 최종 승인 상태가 아니다.
- 요청 후 원본 실행문·설정·기준 이미지가 바뀌면 재개와 등록을 중지한다. 동시에 같은 실행을 처리하지 않도록 잠금 파일을 사용한다. 비정상 종료 뒤 남은 잠금은 실행 중인 프로세스가 없는지 확인한 후 처리한다.
- `attach-reg`는 기존 RAW·최종 승인 기록·패키지를 변경하지 않는다. 같은 바이트의 결과를 다시 연결하면 기존 파일·연결을 재사용한다.
- 현재 저장소의 기본 무시 규칙에 따라 실행 이미지와 JSON은 Git에 포함되지 않는다.
- API 계약은 [공식 명세](https://image.novelai.net/docs/index.html)를 기준으로 하며 모델 해시와 요청 버전은 2026-11-15 공식 웹 클라이언트에서 확인했다. 실제 생성 검증은 API 사용을 지시받은 작업에서 수행한다.
