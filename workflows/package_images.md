# 패키지 대표·서브 이미지

이 문서에서 **소유 패키지**는 이미지를 등록할 패키지를 뜻한다. **구성 키**는 그 패키지의 기본본이나 변형본을 가리키는 키다. 예를 들어 `base`는 기본본, `v01`은 변형본의 구성 키다.

| 순서 | 하는 쪽 | 내용 |
|---|---|---|
| 1 | 사용자 | 어느 패키지의 어느 구성에 대표 또는 서브 이미지를 만들지 요청한다. |
| 2 | 에이전트 | [구성을 확인](#요청과-구성-확인)하고 [생성 구성](#생성-구성)에 따라 [프롬프트를 제출](#프롬프트-제출과-생성)한다. |
| 3 | 사용자 | NovelAI에서 이미지를 생성해 전달한다. |
| 4 | 에이전트 | [실행값을 확인](#결과-확인과-명시적-선택)하고 결과를 설명한다. |
| 5 | 사용자 | 채팅에서 대상과 용도를 명시해 선택한다. |
| 6 | 에이전트 | 선택된 이미지를 소유 패키지에 등록한다. [교체와 해제](#교체와-해제)도 사용자 지시에 따른다. |

## 목적과 범위

사용자가 기존 스타일·캐릭터·청크의 특정 구성을 보여주는 이미지를 요청하면, 생성용 프롬프트를 제출한다. 사용자가 이미지를 생성한 뒤 채팅에서 결과를 명시적으로 선택하면 해당 패키지에 등록한다.

이 절차는 기존 승인 구성을 사용한다. 샘플에서 묶음을 저장할 때는 [패키지 등록](package_registration.md), 실행 태그를 변경할 때는 [선택적 교정과 승인](refine.md)을 따른다. HTML은 결과를 보여주는 화면이고, 대표·서브 선택은 채팅에서 진행한다.

**세부 규칙**

- 이 작업으로 샘플 ID·샘플 폴더·RAW·REG·REFINE JSON·샘플 인덱스 행을 만들지 않는다.
- 이미지와 실제 생성 정보는 [패키지 자체 이미지](../formats/storage.md#패키지-자체-이미지)에 따라 소유 패키지의 구성에 직접 저장한다.

## 요청과 구성 확인

1. 사용자가 요청한 소유 패키지 ID와 구성 키(`base`, `v01` 등), 대표 또는 서브의 용도를 확인한다.
2. 해당 종류의 FORMAT·INDEX와 실제 패키지 구성을 읽는다.
3. 사용하는 입력 슬롯과 청크의 모든 역할 연결을 확정한다.

**세부 규칙**

- 2: 캐릭터용 스타일, 청크용 스타일·캐릭터도 실제 구성 키와 전체 Prompt·UC를 확인한다. 선택이 정해져 있지 않고 결과에 영향을 주면 필요한 선택만 확인한다.
- 3: 누락된 역할이나 없는 패키지를 임의의 태그로 대신하지 않는다.

## 생성 구성

| 소유 패키지 | 사용할 구성 |
|---|---|
| 스타일 | 해당 스타일 + [공통 랜덤 템플릿](#스타일-공통-랜덤-생성) |
| 캐릭터 | 선택한 기존 스타일 + 해당 캐릭터 + [구도](#캐릭터-생성용-구도)·[포즈·배경](#캐릭터-생성용-포즈배경-랜덤) |
| 청크 | 선택한 스타일·캐릭터 + 장면 청크의 모든 역할 |

기존 구성의 문자열은 그대로 사용한다. 서브 이미지도 같은 규칙으로 구성한다.

**세부 규칙**

- 스타일: 해당 스타일의 Prompt·UC를 사용하고 BASE만 사용한다.
- 캐릭터: 선택한 기존 스타일의 Prompt·UC와 해당 캐릭터의 Prompt·UC를 사용한다. BASE 인원 태그와 실제 캐릭터 슬롯을 정한다.
- 청크: 장면 청크의 모든 역할별 선두·본문 Prompt·UC를 사용한다. 인원·장면 표현은 청크에 포함되므로 자동 추가하지 않는다. 필요한 인물 역할과 캐릭터 슬롯을 연결한다. 기존 부분 청크에만 [기본 인물](#청크-생성용-기본-인물) 규칙을 적용한다.
- 종류별 범위는 [스타일](../library/styles/FORMAT.md#대표서브-이미지)·[캐릭터](../library/characters/FORMAT.md#대표서브-이미지)·[청크](../library/chunks/FORMAT.md#대표서브-이미지)를 따른다.
- 그대로 사용하는 대상은 기존 구성의 문자열·가중치·중복·보호 구문이다. 신규 장면 청크의 인원·전역 표현도 함께 조립한다.
- 묶음 연결에는 [슬롯 배치](../formats/prompt_rules.md#입력-슬롯과-재사용-묶음)와 [조립 규칙](../formats/storage.md#refine-json)을 사용한다.
- 서브: 다른 기존 구성이나 seed를 사용하면 변경 내용을 밝히고 [실행문 대조](../formats/storage.md#실행문-대조)의 비교 기준을 적용한다.

### 스타일 공통 랜덤 생성

스타일 이미지는 모든 스타일에 같은 랜덤 템플릿을 쓰고 스타일 Prompt·UC만 교체한다. 템플릿은 NovelAI의 `||선택지1|선택지2||` Prompt Randomizer로 다음을 무작위로 고른다.

- 인원 1~2명·성별·연령대
- 동적 자세의 강조 또는 억제
- 물건 들기의 강조 또는 억제
- 실내 또는 실외

사용자가 구체적인 조건을 명시하면 그 요청 범위에서 별도 구성한다.

**세부 규칙**

- 에이전트가 한 번 추첨해 고정 태그를 제출하거나 스타일마다 장면을 다시 설계하지 않는다.
- 구체적인 머리·눈·체형·의상·표정·동작·소품 종류·장소·구도는 자동 지정하지 않는다.
- 기본 템플릿의 문자열 정본은 [style-random-v1](../formats/style_image_profiles/style-random-v1.json)이다.

  BASE는 `base_prefix` → 저장된 스타일 Prompt → `base_suffix`를 빈 줄 하나로 연결한다. BASE UC는 저장된 스타일 UC 그대로이며 Character 슬롯은 만들지 않는다.
- 인원·성별·연령대는 첫 랜덤 구문에 묶고, 나머지 세 항목은 각각 선택한다. 연령 태그 없는 선택지는 연령 미지정이다. 템플릿의 선택지 개수를 유지한다.
- 배경은 실내외 범주와 단순 배경 억제만 전달한다.
- 모델·해상도·seed·설정은 별도로 안내하고, 실제 랜덤 선택 결과는 [결과 확인](#결과-확인과-명시적-선택)에서 대조한다.
- 사용자 조건으로 별도 구성한 경우 해당 템플릿을 기록한다.
- 프롬프트 출력 명령은 [스타일 랜덤 프롬프트 출력](../scripts/README.md#스타일-랜덤-프롬프트-출력)을 따른다.
- 이미지에 사용된 템플릿 버전은 고정한다. 변경 시 다음 버전 파일을 추가한다.
- 구문 근거: [NovelAI Prompt Randomizer](https://docs.novelai.net/en/image/promptrandomizer/).

### 캐릭터 생성용 구도

캐릭터 이미지에서 지원하는 추가 구도 태그는 `full body` 하나다. 사용자가 전신 구도를 요청했거나, 제안한 전신 구도를 적용해 생성한 결과를 선택한 경우에 붙일 수 있다.

**세부 규칙**

- 위치는 BASE 첫 묶음의 인원 태그 뒤이며 한 번만 붙인다. 예: `1girl, full body,` → 빈 줄 하나 → 저장된 스타일 Prompt.
- 기존 부분 청크의 적용 범위는 [기본 인물 구성](#청크-생성용-기본-인물)을 따른다.
- 구도는 이미지의 실제 `execution.base.prompt`에 보존한다. 캐릭터·스타일의 Prompt·UC와 `components`는 유지하고, 전체 실행문과 원본 메타데이터를 대조한다.

### 캐릭터 생성용 포즈·배경 랜덤

캐릭터 이미지의 배경 기본값은 실내·실외 랜덤이다. 사용자가 캐릭터에 맞는 연출을 요청하면 그 범위에서 전용 배경과 포즈를 구성하며, 전용 배경은 기본 랜덤을 대체한다. 포즈는 `dynamic pose`·`fighting stance` 같은 범주로 제안한다.

**세부 규칙**

- 공통 배경 기본값은 `||indoors|outdoors||,`와 `-1::simple background ::,`다.
- 전용 배경을 쓰면 기본 실내·실외 랜덤을 중복 추가하지 않는다. 손·발의 세부 배치나 표정을 자동 지정하지 않는다.
- 승인된 캐릭터·스타일 문자열과 UC는 유지한다. 생성용 배경은 BASE 스타일 뒤에, 포즈는 CHARACTER_1의 캐릭터 뒤에 빈 줄 하나로 연결한다. 이 경로는 BASE 스타일 하나와 CHARACTER_1 캐릭터 하나만 지원하며, 추가 연출을 재사용 패키지나 별도 청크로 저장하지 않는다.
- 등록할 이미지에 사용된 추가 입력은 `formats/character_image_profiles/character-chNNN-vN.json`에 버전을 고정한다.

  구조는 `schema_version: 1`, `id`, `character: {id, variant}`, `base_prefix`, `base_suffix`, `character_suffix`다. 전체 스타일·캐릭터 문자열은 복제하지 않는다.

  갤러리의 `prompt_template`가 이 ID를 참조한다.
- 원본의 입력 템플릿과 모든 슬롯의 `actual_prompts`를 대조한다. 등록 시 `execution`에는 랜덤 선택이 완료된 전체 Prompt·UC와 실제 설정만 저장한다.
- 이미지가 연결된 프로필에 새 생성 구성이 필요하면 다음 버전을 만든다. 캐릭터 자료를 삭제할 때 그 캐릭터에만 소속된 프로필도 함께 삭제한다.

### 청크 생성용 기본 인물

기존 부분 청크(스키마 1~3)에만 적용한다. 새 장면 전체 청크는 자체 인원·장면 표현을 유지하며, 필요한 캐릭터 구성을 명시한다.

| 입력 칸 | 구성 |
|---|---|
| BASE Prompt | `1girl,`·`1boy,`·`1other,` 중 하나 → 스타일 Prompt |
| BASE UC | 스타일 UC |
| CHARACTER_1 Prompt | BASE 인원과 대응하는 `girl,`·`boy,`·`other,` → 청크 역할의 전체 Prompt |
| CHARACTER_1 UC | 해당 역할의 UC |

**세부 규칙**

- 현재 등록 지원 범위는 캐릭터 역할 하나를 `CHARACTER_1`에 연결한 단일 인물 청크다.
- BASE의 인원 태그는 실제 실행에서 확인한 값이다. 전신 요청 시 그 뒤에 `full body,`를 한 번 붙일 수 있다.
- 표의 `→`는 빈 줄 하나로 연결한다.
- 고정 외형·다른 동작·추가 UC는 이 최소 구성에 임의로 넣지 않는다.
- `components`에는 사용한 스타일과 소유 청크만 기록한다. 기본 인물 식별과 전신 구도는 이미지 `execution`에만 보존한다.
- 검증은 인원과 성별 대응, 역할 연결, 전체 실행문과 원본 메타데이터를 모두 대조한다.

## 프롬프트 제출과 생성

1. 소유 패키지와 사용할 모든 패키지의 ID·구성 키, 입력 슬롯·역할 연결을 안내한다.
2. BASE와 사용하는 캐릭터 슬롯의 Prompt·UC 전체를 제출한다. 사용자는 이 최종 입력본으로 NovelAI 이미지를 생성한다.
3. 모델·해상도·seed·생성 설정과 값의 출처를 안내한다.
4. 사용자가 이미지를 전달하면 [결과 확인과 명시적 선택](#결과-확인과-명시적-선택)으로 진행한다.

**세부 규칙**

- 생성 프롬프트 제출 전에 별도 승인 단계를 추가하지 않는다.
- 2: `BASE Prompt`·`BASE UC`, 이어서 캐릭터 슬롯 순서로 입력 칸별 코드 블록에 제출한다. 비어 있는 칸은 `비움`으로 표시한다.
- 3: 코드 블록 밖에 안내한다. 기존 패키지 자체 이미지에서 확인한 설정 또는 사용자 지정값을 사용할 수 있다. 새로 제안한 값은 제안이라고 밝힌다. 무작위 seed를 안내한 경우 반환 이미지에서 실제 seed를 확인한다. `Quality Tags: None`, `UC Preset: None`을 명시한다.
- 4: 반환 이미지가 아직 선택되지 않았으면 채팅에서 비교한다.

## 결과 확인과 명시적 선택

1. 반환된 원본에서 실제 실행값을 확인한다.
2. 자동 프리셋 검사와 실행문 대조를 적용한다. 프리셋 재첨가가 의심되거나 대조할 수 없으면 평가·등록을 중지하고 확인 가능한 원본을 요청한다.
3. 그 밖의 실행 차이도 사용자에게 알린다.
4. 소유 패키지의 특징이 어떻게 나타났는지 이미지를 보고 설명한다.
5. 사용자가 `이 이미지를 st001/base 대표로 지정`, `이 이미지는 ch001/v01 서브에 추가`처럼 대상과 용도를 명시하면 등록한다.
6. 이미지 원본과 실제 생성 정보를 소유 패키지에 보존하고, 선택한 대표·서브 참조를 갱신한다.

**세부 규칙**

- 1: 확인 대상은 원본의 형식과 실제 전체 Prompt·UC·캐릭터 순서·좌표·seed·모델·해상도·생성 설정이다. 메타데이터가 부족하면 실제 입력값을 확인한다. 추출은 메모리에서 수행한다.
- 1 (랜덤 스타일·캐릭터 이미지): 메타데이터의 입력 템플릿을 제출문과 대조하고, `Comment.actual_prompts`의 모든 슬롯에서 선택 완료 Prompt·UC가 그 템플릿에서 나올 수 있는지 별도로 확인한다.
- 2: [자동 프리셋 검사](../formats/storage.md#자동-프리셋과-실제-실행문)와 [실행문 대조](../formats/storage.md#실행문-대조)를 따른다.
- 3: 소유 패키지의 구성 문자열이 달라진 결과를 해당 구성의 이미지로 등록하지 않는다. 보조 패키지 선택이나 설정을 바꿔 실행했다면 실제 조합을 확인하고, 확인된 기존 구성과 일치하는 경우 그 실제 실행을 기준으로 사용자에게 선택받는다. 임의로 실행문을 고쳐 일치시킨 것으로 처리하지 않는다.
- 5: 앞선 대화로 대상이 명확하면 축약된 선택도 유효하다. 이미지 첨부만으로 등록하지 않는다.
- 6: 보존 대상은 이미지 원본 바이트와 실제 생성 정보다. 해당 이미지가 다른 패키지를 사용했다는 이유로 그 패키지 갤러리에도 등록하지 않는다. `sources`·샘플·패키지의 Prompt·UC·구성 키는 이미지 등록으로 바꾸지 않는다.
- 6 (랜덤 스타일·캐릭터 이미지): `execution`에는 실제 선택 완료 입력과 실제 설정을 저장하고 `prompt_template`에 사용한 템플릿 ID를 기록한다. 원본 이미지에 남은 입력 템플릿도 등록 검증 대상으로 유지한다.

## 교체와 해제

- 대표는 구성별 최대 한 장이다. 교체는 사용자의 명시적인 교체 지시에 따라 한다.
- 대표에서 내려온 이미지는 갤러리 표시만 해제하고 원본 이미지와 생성 기록은 유지한다.
- 서브는 사용자가 선택한 이미지와 순서로 관리한다.
- 표시 해제와 원본 삭제는 구분한다. 삭제는 별도 요청 범위를 확인해 처리한다.

**세부 규칙**

- 기존 대표가 있을 때 단순 이미지 전달로 교체하지 않는다.
- 기존 대표를 자동으로 서브에 넣지 않는다. 표시만 해제하는 것은 별도 선택이 없을 때의 기본 처리다.
- 같은 이미지를 대표와 서브에 중복 지정하거나 서브 목록에 중복 추가하지 않는다. 서브를 대표로 옮기면 서브 목록에서 제거한다.
- 대표 미지정 시의 출처 샘플 미리보기와 누락 표시는 [HTML 이미지 표시 기준](../viewer/README.md#표시-자료와-대표서브)을 따른다. 출처 미리보기는 대표 지정으로 취급하지 않는다.
- 저장·검증·HTML 갱신은 [저장 규약](../formats/storage.md#패키지-자체-이미지-검증)과 [HTML 안내](../viewer/README.md)를 따른다.
