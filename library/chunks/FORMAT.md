# 청크 패키지 작성 규약

청크는 **한 샘플의 전체 Prompt·UC에서 스타일·캐릭터 묶음을 제외한 나머지 전체**를 함께 저장·선택·재사용하는 단위다. 공통 형식은 [저장 규약](../../formats/storage.md#재사용-패키지-json), 구현 범위는 [적용 상태](../../formats/storage.md#적용-상태)를 따른다.

## 구성과 저장 단위

- 신규 REG·REFINE 구성은 스타일·캐릭터들과 **장면 전체 청크 하나**로 구성한다.
- 스타일은 표현 방식과 관련 UC, 캐릭터는 정체성·외형·체형·함께 유지할 의상과 관련 UC다. 이 두 범위에 속하지 않는 표현을 빠짐없이 청크에 배정한다. 자세·행동·상태·구도·배경·효과뿐 아니라 인원·전역 의도·출력 조건과 관련 UC도 청크에 포함한다.
- 저장 위치는 `library/chunks/ckNNN.json`, 패키지 `schema_version`은 `4`다.
- 청크 하나는 여러 입력칸을 포함할 수 있다.

**세부 규칙**

- 별도의 `other` 묶음을 만들지 않는다.
- 포즈·액션·상태·구도·세팅·효과 분류는 청크 내부의 내용을 읽고 정리하는 기준이다. 분류별 패키지를 생성하거나 독립 교체 가능성을 이유로 여러 청크로 나누지 않는다.
- `category`·`subcategory`를 넣지 않는다.
- ID는 기존 하위 폴더까지 포함한 전체 청크에서 미사용 번호를 선택한다.

## 참여 역할

- `roles`에 BASE와 각 인물 역할의 Prompt·UC를 저장한다. BASE만, 캐릭터 한 명만, **BASE와 캐릭터 한 명**, 여러 캐릭터와 BASE의 조합을 모두 허용한다.
- 패키지 역할에는 대상 종류 `BASE` 또는 `CHARACTER`를 기록하고, 실행 시 `BASE`·`CHARACTER_N` 슬롯에 연결한다.
- 인원·전역 의도처럼 스타일보다 앞에 들어갈 문자열은 같은 역할 안의 선택 필드 `prefix_prompt`·`prefix_uc`로 저장한다. 나머지는 `prompt`·`uc`다.
- 조립은 각 슬롯의 선두 문자열 → 묶음 배열 순서의 본문이다.
- 모든 역할을 연결한 뒤 청크 전체를 적용·교체·제거한다.

**세부 규칙**

- BASE 역할은 최대 하나, 서로 다른 인물 역할은 서로 다른 캐릭터 슬롯에 연결한다.
- 선두 표현도 청크의 일부이며 별도 패키지나 기타 묶음으로 분리하지 않는다.
- Prefix와 본문은 모두 완성 문자열이며 가중치·내부 개행을 보존한다. [문자열 조립](../../formats/storage.md#문자열-조립)을 따른다.
- 역할 누락·중복 슬롯·대상 종류 불일치가 있으면 부분 적용하지 않는다.

## 내용 분류

- `variants.<키>.content_rating`에 `sfw` 또는 `nsfw`를 지정한다. 모든 역할의 선두·본문 Prompt가 표현하는 장면 전체로 판단한다.
- 성적 행위·성적 노출을 직접 표현하는 구성은 `nsfw`, 그런 표현이 없는 구성은 `sfw`다.

**세부 규칙**

- UC의 억제 대상만으로 NSFW로 분류하지 않는다.
- 출처 샘플의 분류를 자동 상속하거나 `nsfw`·`sex`의 유무만으로 판정하지 않는다. 불명확하면 내용을 확인한다.

## 가중치

- 기존 가중치의 부호·수치·범위를 유지한다.
- [선택적 REFINE](../../workflows/refine.md#방향-선택)에서 확인된 충돌 또는 중요한 특징의 미구현을 교정할 때만 관련 부분을 조절한다. 스타일·캐릭터·청크 모두 같은 최소 변경 원칙을 적용한다.
- 가중치는 Prompt·UC 문자열 안에 저장한다.
- 수정 전후는 [실행문 대조](../../formats/storage.md#실행문-대조)에 따라 같은 seed·설정으로 비교한다.

**세부 규칙**

- 양수 가중치 제거, 음수를 `-1`로 통일하는 초기화, 청크 전체를 감싸는 새 가중치를 자동 적용하지 않는다.
- 별도 수치 필드나 조립 시 변환을 두지 않는다.

## 이름

- 장면 전체를 식별할 수 있는 한국어 이름을 사용한다. 필요한 경우 `장면 핵심 — 구별되는 조건`으로 적는다.
- INDEX와 구성의 `name`을 함께 갱신한다.

## 기존 청크와의 판정

[패키지 등록](../../workflows/package_registration.md)에서 지정된 장면 전체 청크를 비교한다.

| 비교 결과 | 판정 |
|---|---|
| 장면의 재사용 범위·역할 구성이 같고 모든 역할의 선두·본문 Prompt·UC가 [실행문 대조](../../formats/storage.md#실행문-대조) 기준으로 같다. | 재사용한다. |
| 같은 장면·역할 구성에서 세부 조건·태그·가중치·UC가 다르다. | 바리에이션을 검토한다. |
| 장면의 핵심이나 참여 역할 구성이 다르다. | 새 기본 청크다. |

실제 문자열과 함께 사용할 범위를 비교하고 판정 이유를 채팅에 짧게 설명한다.

**세부 규칙**

- 기존 부분 청크를 여러 개 찾아 조합하는 절차를 신규 작업에 적용하지 않는다.
- 이름이나 판정을 맞추려고 승인된 문자열을 변경하지 않는다.

## 바리에이션 저장

- 기본본은 `variants.base`, 다른 승인 구성은 `v01`, `v02`처럼 마지막 번호 다음 키에 저장한다.
- 같은 ID의 구성은 역할 키와 대상 종류를 유지한다. 각 구성에 모든 역할의 전체 문자열·내용 분류·출처·자체 갤러리를 둔다.
- 출처는 최종 승인된 REG 또는 REFINE 실행 기록과 그 단계의 승인 이미지다.
- 신규 INDEX 행은 `ID | 구성 | 이름 | 내용 분류 | 역할`을 사용한다.

**세부 규칙**

- 차이 태그만 저장하지 않는다.
- 출처는 [최종 승인](../../formats/storage.md#최종-승인-기록)과 [패키지 출처](../../formats/storage.md#인덱스와-샘플-연결)를 따른다.
- 동일한 실행에서 seed만 바뀌면 새 구성 키를 만들지 않는다.

## 대표·서브 이미지

- 선택한 스타일·캐릭터와 청크 전체를 조립한다.
- 필요한 역할을 모두 연결한다. 장면에 인물이 필요하면 그 인물의 캐릭터 구성을 명시한다.
- 저장·검증·대표와 서브 지정·교체·해제는 [패키지 이미지 워크플로우](../../workflows/package_images.md)를 따른다.

## 기존 자료 호환

- `schema_version` 1~3의 부분 청크와 기존 REFINE 실행·승인·갤러리는 과거 기록으로 읽고 검증한다.
- 기존 자료의 통합 요청이 있으면 전체 실행·승인 근거를 확인해 별도로 처리한다.
- HTML의 기존 부분 청크는 조회용으로 유지한다. 새 구성기는 장면 전체 청크 하나를 선택하며, 과거 REFINE은 기존 순서대로 조회할 수 있다.

**세부 규칙**

- 기존 샘플의 청크들을 새 장면 청크로 자동 합치거나 재승인하지 않는다.
