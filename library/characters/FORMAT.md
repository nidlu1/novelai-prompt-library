# 캐릭터 패키지 작성 규약

캐릭터 패키지는 승인된 정체성·외형·체형·함께 유지할 의상과 관련 UC를 저장하는 재사용 묶음이다. 자세·행동 청크를 합치지 않는다.

공통 형식은 [storage.md](../../formats/storage.md#재사용-패키지-json)를 따른다. 기본 캐릭터 ID는 `ch001`부터 미사용 번호를 사용한다.

입력 슬롯은 실행할 때 지정하며 패키지와 INDEX에는 기록하지 않는다. Prompt·UC를 같은 대상 슬롯에 통째로 배치한다. 사용한 Prompt·UC와 입력 슬롯은 승인 대상 REG 또는 REFINE 실행 기록에 보존한다.

## 기존 캐릭터와의 판정

[패키지 등록](../../workflows/package_registration.md)에서 지정된 캐릭터를 판정할 때 INDEX와 실제 패키지를 확인해 인물의 정체성과 Prompt·UC 구성을 비교한다.

| 비교 결과 | 판정 |
|---|---|
| 동일 인물이며 Prompt·UC가 [실행문 대조](../../formats/storage.md#실행문-대조) 기준으로 같다. | 기존 패키지를 재사용한다. |
| 동일 인물이며 외형·체형·의상·장비·가중치·관련 UC 구성이 다르다. | 같은 기본 ID의 바리에이션으로 분류한다. |
| 다른 인물이거나 동일 인물이라는 근거가 부족하다. | 별도 기본 ID로 분류한다. |

비교한 기본 ID와 동일 인물의 근거·구성 차이를 사용자에게 짧게 알린다.

**세부 규칙**

- 실행 시 입력 슬롯이 달라지는 것만으로 별도 패키지를 만들지 않는다.
- OC는 외형이 비슷하다는 이유만으로 동일 인물로 묶지 않는다.
- 기존 패키지에 맞추려고 승인된 태그를 변경하지 않는다.

## 바리에이션 저장

- 기본은 `chNNN.json`의 `variants.base`에 저장한다. 등록 대상이 바리에이션이면 같은 파일에 `v01`부터 마지막 번호 다음의 키를 추가한다.
- 이름은 `<캐릭터 이름> · <구성을 구별하는 특징>`으로 쓴다. 특징이 불필요한 기본본에서는 생략할 수 있다.
- INDEX는 `ID | 구성 | 이름` 열로 기본 ID의 JSON과 구성 키를 연결하며, `base` 아래에 변형 번호순으로 배치한다.

**세부 규칙**

- 전체 문자열·출처와 슬롯의 취급은 [패키지 JSON](../../formats/storage.md#재사용-패키지-json)을 따른다.
- 샘플은 실제 사용한 JSON 경로와 구성 키를 참조한다.
- 동일 실행의 seed 변주나 이미지에서만 보이는 차이로 새 구성 키를 만들지 않는다.

## 대표·서브 이미지

- 선택한 기존 스타일 구성과 이 캐릭터 구성의 전체 Prompt·UC를 조합한다. BASE 인원 태그를 두고, 캐릭터는 정한 입력 슬롯에 통째로 배치한다.
- 요청된 구도는 [캐릭터 생성용 구도](../../workflows/package_images.md#캐릭터-생성용-구도), 생성용 포즈·배경은 [캐릭터 랜덤 구성](../../workflows/package_images.md#캐릭터-생성용-포즈배경-랜덤)을 따른다.
- 대표·서브는 구성별로 사용자가 채팅에서 명시적으로 선택한다. 다른 스타일이나 seed로 만든 서브도 가능하다.
- 저장·교체·해제는 [패키지 이미지 워크플로우](../../workflows/package_images.md)와 [자체 이미지 규약](../../formats/storage.md#패키지-자체-이미지)을 따른다.

**세부 규칙**

- 관련 없는 청크나 장면 표현을 자동 추가하지 않는다.
- 다른 스타일이나 seed로 만든 서브는 이미지의 생성 정보에 실제 조합을 연결한다.
- 캐릭터의 정체성·태그를 바꾸는 요청은 이미지 지정과 구분해 기존 판정·승인 절차를 따른다.
