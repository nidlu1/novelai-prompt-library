# HTML 라이브러리

아틀리에의 샘플·패키지 조회, 프롬프트 구성기와 HTML 갱신기를 제공한다. 도구별 지원 범위는 [적용 상태](../formats/storage.md#적용-상태)를 따른다.

루트의 `library.html`을 더블클릭해 브라우저에서 연다. 서버와 인터넷 연결은 필요하지 않다. 이미지 파일을 상대 경로로 연결하므로 HTML은 루트에 두고, 옮길 때는 폴더 패키지 전체를 함께 옮긴다.

HTML과 브라우저 작업본은 조회용 파생 결과물이다. 원본 JSON·샘플·패키지·승인 기록을 변경하지 않는다. 패키지 이미지의 선택·출처 미리보기·누락 표시는 [패키지 이미지 표시](#패키지-이미지-표시)를 따른다.

## HTML 갱신

HTML에 표시되는 자료나 뷰어 소스를 변경한 뒤에는 루트의 `update_html.cmd`를 더블클릭하고 브라우저를 새로고침한다. 패키지 자체 이미지의 등록·대표 교체·서브 추가·해제도 갱신 대상이다.

갱신에는 Python 3.10 이상이 필요하다.

**세부 규칙**

- 에이전트는 루트에서 `./update_html.cmd --no-pause`를 실행하고 성공 여부와 자료 확인 경고를 확인한다. 실패하면 기존 HTML을 유지하고 갱신 실패를 알린다.
- 문서나 읽기·검색 도구만 수정했으면 갱신하지 않는다.
- Python 실행 파일은 `VIEWER_PYTHON` 환경 변수, 설치된 Codex의 Python, `py -3`, `python` 순서로 찾는다.

## 화면 구성

### 샘플과 패키지 조회

- 샘플의 SFW/NSFW 필터는 [샘플 인덱스](../formats/storage.md#샘플-인덱스)의 분류를 사용한다.
- 샘플 표지는 [최종 승인 기록](../formats/storage.md#최종-승인-기록)이 지정한 REG 또는 REFINE 이미지다.
- 샘플 상세에는 최종 승인 단계를 표시하고 그 이미지·프롬프트·실제 설정을 기본 선택한다. 비교 영역에는 기록된 단계별 자료를 표시한다.
- 보관 대상으로 선택된 `draft-refine-<번호>`는 별도의 후보·비교 영역에 표시한다.
- 패키지는 구성별 대표·서브와 대표 미지정 시의 출처 샘플 미리보기를 표시한다.
- 청크 목록에는 장면 전체와 기존 부분 청크를 구별해 표시한다. 내용 분류 필터는 샘플의 분류와 독립적이다.

**세부 규칙**

- 미승인 REFINE이 있어도 승인된 REG를 유지한다. 승인 전에는 최종 이미지 없이 단계별 결과만 표시한다. 승인 이미지가 누락되면 경고한다.
- 기존 승인본 해석은 저장 규약의 호환 조건만 사용한다.
- `draft-refine`에 현재 실행값을 비교본의 실행값으로 사용하거나, 비교본을 최종본으로 자동 선택하지 않는다.

### 묶음 목록과 구성 선택

- 목록은 표시 그룹당 카드 하나를 보여준다. 같은 스타일·캐릭터·청크 ID의 `base`·`v01` 등은 자동으로 묶고, 서로 다른 샘플·패키지 ID는 아래 표시 그룹에 명시한 경우 함께 보여준다.
- 그룹 카드는 이름과 항목 수를 표시한다. 상세 상단의 썸네일·이름 선택 영역에서 구성 하나를 선택하면 그 항목의 이미지·프롬프트·실제 설정·승인 상태를 보여준다.
- 샘플 썸네일은 각 샘플의 최종 승인 이미지다. 패키지 썸네일은 각 구성의 [이미지 표시 기준](#표시-자료와-대표서브)을 따른다.
- 검색은 그룹 이름·ID와 개별 항목의 이름·ID·프롬프트를 포함한다.
- 구성기의 선택 목록은 그룹을 펼친 뒤 정확한 구성 하나를 선택한다. 씬 편집의 샘플 불러오기·패키지 교체 목록도 같은 그룹으로 묶는다.

**세부 규칙**

- 서로 다른 종류를 한 그룹에 넣거나 이름·태그 유사도로 자동 편입하지 않는다.
- 기존 개별 샘플·패키지 주소로 들어가도 같은 그룹을 탐색할 수 있다.
- 그룹은 이미지 소유·승인을 갖지 않으며, 진입 대상 구성의 이미지를 표시한다. 다른 구성의 이미지로 대체하지 않는다.
- 분류·구성 필터와 검색을 개별 항목에 먼저 적용하고 일치한 항목을 그룹으로 모은다. 기본 구성만 일치해야 그룹을 표시하는 제한을 두지 않는다. 결과 수는 카드 수와 개별 항목 수를 구별한다.
- 카드의 진입 대상은 표시 대상 안에 있는 그룹 기본 항목, 없으면 그룹 순서상 첫 일치 항목이다. 검색으로 특정 구성만 남으면 바로 그 구성으로 열린다. 상세의 구성 선택 영역도 현재 내용 분류 필터를 따른다. 기존 개별 주소로 필터 밖 항목을 직접 열면 그 지정 항목도 선택 영역에 표시한다.
- 그룹을 통째로 실행에 적용하지 않는다.

### 표시 그룹 저장

표시 그룹의 정본은 `viewer/groups.json`이다. 실행·승인·패키지 형식과 분리된 조회용 정보다. 미지정 파일은 자동 패키지 그룹과 개별 샘플로 표시한다.

```json
{
  "schema_version": 1,
  "groups": [
    {"id": "s0003", "kind": "sample", "name": "S0003 묶음", "members": ["s0003", "s0004"], "default": "s0003"}
  ],
  "package_aliases": {}
}
```

- `kind`는 `sample`, `style`, `character`, `chunk`다. `id`는 같은 종류 안에서 고유한 표시 그룹 식별자, `name`은 표시 이름이다.
- `members`는 같은 종류의 기존 기본 ID 배열이며 배열 순서로 표시한다.
- `default`는 `members` 중 하나다.
- 명시하지 않은 샘플은 개별 카드, 명시하지 않은 패키지는 같은 기본 ID끼리 카드 하나로 표시한다.
- 선택 필드 `package_aliases`는 편입 전의 `종류/ID/구성`을 현재 구성 주소로 연결한다.

**세부 규칙**

- `id`는 소문자·숫자·`_`·`-`를 사용하고 소문자나 숫자로 시작한다.
- 패키지 ID는 그 패키지의 모든 구성을 `base`·변형 번호순으로 포함한다. 구성마다 그룹을 나누지 않는다. 각 항목은 한 그룹에만 속한다.
- 패키지는 `default`로 지정한 ID의 `base`로 진입한다. 기본 항목 지정은 최종 승인이나 패키지 대표 지정이 아니다.
- 목록 순서는 그룹의 가장 앞선 기존 항목 순서를 따른다.
- 현재 패키지 키와 충돌하거나 다른 종류·없는 구성을 가리키는 별칭은 허용하지 않는다. 별칭은 HTML 주소 호환만 담당하며 실행·출처의 실제 파일 참조는 편입 시 함께 갱신한다.
- 중복 그룹·중복 소속·없는 항목·그룹 밖의 기본 항목·잘못된 별칭은 생성 오류다. 갱신 실패 시 기존 HTML을 보존한다. 그룹 변경 후 HTML을 갱신한다.

### 프롬프트 구성과 복사

구성 순서는 **스타일·설정 → 캐릭터 → 장면 청크 → 확인·복사**다.

- 장면 전체 청크 하나를 선택한다. 다른 청크를 선택하면 교체된다.
- 직접 장면을 작성할 때는 청크를 고르지 않고 최종 단계의 입력을 사용한다. BASE 앞부분·슬롯별 추가 Prompt·UC는 하나의 장면 청크 역할에 합쳐진다.
- 청크의 BASE·인물 역할을 실제 슬롯에 모두 연결한다.
- 스타일의 설정 출처는 해당 구성의 지정된 대표·서브 이미지다.
- 입력칸별 복사와 수동 복사를 제공한다.
- 상태는 현재 창에서만 유지되고 새로고침하면 초기화된다.

**세부 규칙**

- 여러 장면을 합치지 않는다. 기존 부분 청크는 목록에서 조회하지만 새 구성기의 선택 대상은 아니다.
- 기존 청크에 추가 입력하면 수정 작업본이다.
- 역할 누락·중복 슬롯·대상 불일치는 복사를 막는다. 슬롯 삭제 시 다른 인물에 자동 연결하지 않는다.
- 선두 문자열과 본문을 모두 보존한다. 청크에 인원 표현이 이미 있으면 자동으로 인원을 추가하지 않는다. 가중치는 [가중치 규칙](../chunks/FORMAT.md#가중치)을 따른다.
- 미확인 설정은 기본값으로 채우지 않는다.
- `비움`과 `미기록`을 구별한다.

## 씬 내부의 분류별 편집

상단 `씬 편집`, 샘플 상세의 `승인 구성·작업본을 씬으로 편집`, 구성기의 `현재 조합을 씬으로 편집`에서 시작한다.

### 작업본 불러오기와 표시 순서

- 최종 승인본이 있으면 그 REG 또는 REFINE 묶음을 불러온다. 승인 전에는 저장된 묶음 실행을 작업본으로 불러올 수 있다.
- 스타일·캐릭터는 별도로 교체하며, 신규 청크는 `장면 전체` 한 블록에서 모든 역할과 선두·본문 Prompt·UC를 편집한다.
- 기존 REFINE의 여러 부분 청크와 기타는 과거 구조대로 읽는다.

**세부 규칙**

- 승인된 평면 REG에 묶음 정보가 없으면 임의 의미 분석으로 편집 블록을 만들지 않는다.
- 분류 필터는 실제 조립 순서를 바꾸지 않는다.

### 블록 편집과 복원

- 장면 전체 청크는 전체 패키지로 교체하고 역할별 입력칸을 연결한다. 선두 Prompt·UC도 표시·수정·복원한다.
- 블록 활성화·비활성화·비우기·원본 복원은 모든 역할의 선두와 본문에 함께 적용한다. 전체 복원은 문자열과 순서를 되돌린다.

**세부 규칙**

- 신규 장면 청크가 있으면 별도 편집 블록을 추가하지 않고 그 청크의 역할을 편집한다.
- 과거 부분 청크 작업본의 기존 편집 기능은 유지한다.

### 최종 입력과 작업본 상태

- 직접 입력은 양끝 공백과 끝 쉼표를 정리하되 내부 문자열·가중치는 보존한다. 슬롯별 전체 출력과 빈 UC를 명시한다.
- 변경 작업본은 `미검증 · 변경 구성`으로 표시한다. 이미지 검증·승인·저장은 채팅의 선택적 교정·승인 절차를 따른다.
- 브라우저 작업본은 임시 편집 상태이며 새로고침하면 초기화된다.

## 패키지 이미지 표시

### 표시 자료와 대표·서브

- 저장 정본은 [패키지 자체 이미지](../formats/storage.md#패키지-자체-이미지)의 구성별 `gallery`다.
- 목록 카드와 구성 선택 썸네일에는 대표 이미지를 우선 표시하고, 대표 미지정 시에는 해당 구성의 출처 샘플 이미지를 `출처 샘플` 표시와 함께 보여준다.
- 상세에는 대표 또는 출처 샘플 미리보기와 지정된 서브 이미지를 표시한다. 출처 미리보기에는 샘플·단계와 샘플 링크를 표시하고, 서브는 지정 순서를 따른다.
- 갤러리 카드는 이미지·대표/서브 구분·이미지 ID만 표시하고 이미지 확대를 제공한다.

**세부 규칙**

- 대표는 `gallery.representative`, 서브는 `gallery.sub_images`를 사용한다. 출처 미리보기는 `sources`의 기록 순서에서 승인·패키지 연결과 실제 파일을 확인할 수 있는 첫 `image`를 사용한다. 해당 `sample`의 REG·REFINE 단계에 연결된 승인 이미지여야 하며, 현재 구성과 일치하는 패키지 묶음이 있어야 한다.
- 최초 RAW·미승인 결과·후보·현재 샘플 표지·다른 구성·서브 이미지를 출처 대신 선택하지 않는다. 샘플의 최종 단계가 바뀌어도 기록된 출처 이미지와 승인이 유지되면 그 이미지를 사용한다.
- 대표도 유효한 출처 이미지도 없으면 `대표 이미지 미지정`을 표시한다. 대표가 지정되어 있는데 기록·파일이 누락되면 `대표 이미지 확인 필요`를 유지하고 출처로 대체하지 않는다. 출처 참조·이미지 오류도 자료 확인 사항에 표시한다.
- 출처 미리보기는 HTML 표시용이다. `gallery`·대표 지정·승인 기록을 변경하거나 구성기의 설정 가져오기 항목에 추가하지 않는다.
- 대표는 서브 목록에 중복 표시하지 않는다. 대표가 없어도 명시적으로 선택된 서브는 표시할 수 있다.
- 이미지 생성 정보 펼침 영역, 이미지별 Prompt·UC·사용 구성·생성 설정·Seed는 카드에 표시하지 않는다. 패키지 자체의 재사용 Prompt·UC 표시와 구성기의 설정 가져오기는 유지한다.
- 캐릭터 이미지가 스타일을 사용하거나 청크 이미지가 스타일·캐릭터를 사용해도, 사용된 다른 패키지의 갤러리에 자동 노출하지 않는다. 각 구성의 이미지 소유와 선택을 따른다.

### 지정 변경과 표시 오류

대표·서브 지정·교체·해제는 채팅에서 수행한다. 대표·서브 참조 오류나 이미지 누락은 자료 확인 사항으로 표시한다.

**세부 규칙**

- HTML에 영구 선택·승인 기능을 추가하지 않는다.
- 등록 기록은 있지만 표시 참조가 해제된 패키지 자체 이미지와 미선택 후보는 자동 노출하지 않는다.

## 구성기 저장·조립 기준

- 신규 실행은 [REG·REFINE 묶음 구조](../formats/storage.md#refine-json), 패키지는 [장면 전체 청크](../chunks/FORMAT.md)를 따른다.
- 기존 부분 청크의 대·소분류는 과거 자료 조회와 편집 필터로 유지한다.

**세부 규칙**

- 기존 대·소분류를 새 저장 단위를 나누는 기준으로 사용하지 않는다.

## 소스와 생성물

- `scripts/build_viewer.py`: 폴더의 JSON·샘플 인덱스를 읽고 HTML을 생성한다. 패키지 자체 갤러리·설정 출처와 HTML용 출처 샘플 미리보기를 구성한다.
- `scripts/viewer_groups.py`, `viewer/groups.json`: 표시 그룹·구성 목록·이전 패키지 주소 별칭의 검증과 구성.
- `viewer/template.html`, `styles.css`, `core.js`, `scene.js`, `app.js`: 화면·기본 조립·씬 작업본 편집 소스.
- `library.html`: 데이터·스타일·스크립트가 포함된 생성물.

**세부 규칙**

- `library.html`은 직접 편집하지 않는다.
- 묶음형 REG·REFINE 문자열은 `scripts/assemble_refine.py`로 조립한다.
- 패키지 사용 관계는 `bundles[].package`의 파일·구성 키와 실제 실행 문자열을 대조해 만든다.
- 패키지 이미지의 `execution`은 검증과 구성기 설정 출처로 사용한다. 현재 패키지 태그로 과거 실행을 재생성하지 않는다.
- 최종 승인 선택은 `scripts/sample_approval.py`로 공통 해석한다.
- 생성 중 잘못된 JSON·슬롯·경로가 발견되면 실패하고 기존 HTML을 보존한다. 이미지 누락이나 패키지 연결 불일치는 화면의 자료 확인 사항에 표시한다.
- 원본 저장과 조립 규칙은 [저장 규약](../formats/storage.md), [프롬프트 규칙](../formats/prompt_rules.md)을 따른다.

## 개발 검증

루트에서 다음 검사를 실행한다. Python 검사는 임시 자료로 자체 이미지 소유·선택·메타데이터 대조와 생성 실패 시 기존 HTML 보존을 확인하고, JavaScript 검사는 조립 문자열·역할 연결을 확인한다.

```text
python -X utf8 -B -m unittest discover -s scripts
node viewer/test_core.cjs
node viewer/test_scene.cjs
node viewer/test_browser.cjs
node viewer/test_groups_browser.cjs
```

일반 사용과 HTML 갱신에는 Node.js나 Playwright가 필요하지 않다.

**세부 규칙**

- `viewer/test_browser.cjs`는 Playwright와 Chromium 계열 브라우저가 있는 개발 환경에서 현재 `library.html`과 임시 테스트 자료의 `file://` 동작을 검사한다.
- `viewer/test_groups_browser.cjs`는 임시 중립 자료로 그룹 탐색·분류 필터·기존 주소 별칭·개별 구성 선택·모바일 표시를 검사한다.
- Playwright가 별도 경로에 있으면 `NODE_PATH`를 지정한다. `VIEWER_PYTHON`으로 Python 실행 파일을, `VIEWER_BROWSER`로 브라우저 실행 파일을 지정할 수 있다.
- 브라우저를 지정하지 않으면 Windows의 Chrome·Edge 기본 설치 경로, Playwright의 Chromium 순으로 찾는다.

패키지 자체 이미지 검사에는 다음 사례를 포함한다.

- 대표 미지정 시 해당 구성의 승인된 출처 이미지와 `출처 샘플` 표시, 출처 순서·정확한 단계·이미지 유지, 자체 갤러리·설정 출처·원본 기록 불변.
- 대표 지정 우선, 대표 기록·파일 누락 시 출처로 대체하지 않음, 유효한 출처가 없으면 미지정 표시, 대표·서브 중복 없음, 사용자 지정 순서 유지.
- 같은 스타일을 사용하는 캐릭터·청크 이미지가 스타일 갤러리에 자동 추가되지 않음.
- 후보·과거 해제 이미지·출처에 지정되지 않은 사용 샘플 이미지가 패키지 갤러리나 출처 미리보기에 자동 노출되지 않음.
- 갤러리 카드의 이미지 생성 정보 미표시, 구성기에서 설정 미기록과 빈 값 구분.
- 패키지 이미지 등록·교체가 샘플 생성이나 인덱스 변경을 유발하지 않음.
- `file://`에서 이미지 경로·확대·복사·설정 선택이 동작하며 외부 요청 없이 표시됨.
- 그룹당 카드 하나, 개별 주소에서 구성 전환, 변형본 검색·분류 필터·정확한 구성 선택, 그룹 오류 시 기존 HTML 보존.
